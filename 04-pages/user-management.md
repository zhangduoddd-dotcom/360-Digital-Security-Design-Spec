# 用户管理页规范
## User Management Page Standard

Keywords: user management, account, role, permission, organization, backend, ai readable, html preview

本文定义后台系统中的用户、账号、角色、组织、用户组及相关权限管理页面。AI 生成用户管理 HTML Demo 时，应同时参考列表页、表单页、详情页和权限状态规则。

## 1. 页面定位

用户管理用于支撑用户信息维护、权限与角色分配、账号状态管控、组织归属维护等功能。页面必须强调安全、可追溯、可确认和低误操作。

## 2. 通用结构

```text
页面标题 / 页级操作
→ 搜索筛选区
→ 组织树 / 用户组筛选（按需）
→ 工具栏 / 批量操作
→ 用户表格
→ 新建 / 编辑抽屉
→ 详情抽屉 / 权限查看
→ 确认弹窗 / Toast 反馈
```

## 3. 核心模块

| 模块 | 必须内容 |
|---|---|
| 搜索区 | 用户名、账号、角色、组织、状态等筛选 |
| 组织树 | 组织层级、搜索、当前选中、数量统计 |
| 用户表格 | 姓名、账号、角色、组织、状态、最近登录、操作 |
| 操作栏 | 新建用户、批量启用、批量停用、导入、导出 |
| 抽屉表单 | 新建 / 编辑用户信息、角色、组织、状态 |
| 详情抽屉 | 基本信息、权限、登录记录、操作记录 |

## 4. 表格与操作

- 用户状态必须用文字和颜色同时表达。
- 高风险操作包括停用、删除、重置密码、解绑 MFA、移除角色。
- 高风险操作必须二次确认，并说明影响范围。
- 批量操作在未选择用户时禁用，并通过 Tooltip 说明原因。
- 行操作超过 3 个时使用 `更多` 收纳低频操作。
- 操作成功或失败后必须 Toast / Message 反馈。

## 5. 新建 / 编辑用户

抽屉表单应包含：

- 基本信息：姓名、账号、邮箱、手机号等。
- 组织归属：部门、用户组、岗位等。
- 权限角色：角色选择、权限说明。
- 状态设置：启用、停用、有效期等。
- 安全项：初始密码、重置密码、MFA 状态等。

规则：

- 必填项明确。
- 账号、邮箱、手机号需要格式校验。
- 角色和组织变更需提示影响范围。
- 保存失败保留已填写内容。

## 6. 权限与安全

- 无权限操作必须 disabled，并说明原因。
- 删除、停用、重置密码等操作必须确认。
- 涉及管理员、超级管理员、系统账号时，应强化提示。
- 权限信息应清楚区分角色、组织、数据范围和功能权限。
- 操作记录应展示时间、操作者和动作。

## 7. HTML Demo 要求

HTML Demo 至少支持：

- 搜索、清空、分页。
- 勾选用户和批量按钮联动。
- 新建用户抽屉打开 / 关闭。
- 编辑用户和查看详情。
- 启用 / 停用确认。
- 删除或重置密码确认。
- 表单校验、提交 loading、成功 / 失败反馈。
- empty、error、disabled 状态展示。

## 8. AI 生成禁止项

- 禁止把用户管理做成普通静态表格。
- 禁止停用、删除、重置密码没有二次确认。
- 禁止权限状态只用颜色表达。
- 禁止无权限操作仍可点击。
- 禁止批量操作不随勾选状态联动。
- 禁止新建 / 编辑表单缺少校验和反馈。

## 9. 验收清单

| 检查项 | 要求 |
|---|---|
| 信息结构 | 用户、组织、角色、状态、最近登录清晰 |
| 搜索筛选 | 支持用户、角色、组织、状态筛选 |
| 批量操作 | 勾选联动、禁用态、确认反馈完整 |
| 安全操作 | 停用、删除、重置密码等有二次确认 |
| 表单交互 | 新建 / 编辑抽屉、校验、提交反馈完整 |
| 权限状态 | disabled 和无权限原因可识别 |
| 预览交互 | 搜索、分页、抽屉、确认、Toast 可验证 |

缺少任一当前业务适用项，视为用户管理 HTML Demo 生成失败。
