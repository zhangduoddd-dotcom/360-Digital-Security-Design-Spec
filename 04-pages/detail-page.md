# 详情页规范
## Detail Page Standard

Keywords: detail page, drawer detail, object detail, timeline, audit, backend, ai readable, html preview, vue codegen

> 本文件定义后台系统中的对象详情、记录详情、审批详情、日志详情、分析详情和抽屉详情页面。
>
> 全局框架、页面容器、颜色、间距、组件尺寸等通用规则，应优先遵循 `03-interaction/platform-frame.md`、`03-interaction/page-container.md`、`01-foundation/tokens.md` 和 `02-components/component-size.md`。

## 1. 页面定位

详情页用于承载单个对象、事件、任务、资产、模型、风险、报告或分析结果的完整信息。核心目标是帮助用户完成“看清对象状态、理解关键原因、定位关联信息、执行下一步操作”。

详情页分为两大类：

```text
抽屉式详情
→ 适合从列表页或监控页快速查看，不打断主流程

独立页面详情
→ 适合信息量较大、层级较深、需要持续阅读或综合分析的场景
```

## 2. 通用信息结构

详情页应按以下顺序组织信息：

```text
标题区 / 对象名称 / 状态标签 / 操作区
→ 基础信息 / 摘要信息 / 关键指标
→ 核心分析区 / 对比区 / 图表区 / 时间线区
→ 详细字段 / 描述表格 / 关联数据
→ 操作建议 / 处置动作 / 导出 / 返回
```

复杂详情页可采用：

```text
顶部对象摘要
→ 标签页 / 锚点导航
→ 分组内容模块
→ 图表 + 表格 + 说明文本组合
→ 底部关联记录 / 空状态 / 操作建议
```

## 3. 抽屉式详情规范

抽屉式详情适用于从列表、告警、事件、监控卡片中快速打开详情。背景页面应保留上下文，并通过遮罩弱化。

布局规则：

- 抽屉从页面右侧滑出。
- 宽度可根据内容复杂度设置为 `560px / 880px / 80%`。
- 信息量较大的分析型详情可使用接近全屏的大抽屉。
- 背景页面应添加半透明遮罩，保持用户对来源页面的上下文感知。
- 抽屉顶部固定显示标题、状态标签和关闭按钮。
- 抽屉内容区纵向滚动，顶部标题区不随滚动消失。
- 抽屉底部如有确认、处置、导出操作，可使用固定底部操作栏。

标题区应包含对象名称、风险等级或状态标签、关闭按钮，以及可选操作按钮，例如导出详情、处置、查看原始数据。

内容区应按模块分段，每段使用小标题和左侧主色竖线加强识别。推荐模块包括综合决策评估、基本信息、应用层模型评估、传输层模型评估、流信息评估、对比分析、处置建议和关联记录。

## 4. 分析评估抽屉详情模板

适用于异常流量、SSL 检测、通信检测、模型评分、安全策略分析等详情。

```text
抽屉标题区：对象名称 + 严重程度标签 + 关闭按钮
→ 综合决策评估：仪表盘评分 + 关键特征标签 + 流量指标卡
→ 基本信息：描述表格
→ 应用层模型评估：热力图 + 排名条形图
→ 传输层模型评估：雷达图 + 指标表
→ 流信息评估：描述表格 + 指标统计卡片
```

综合决策评估区规则：

- 左侧放置半圆仪表盘或评分仪表，突出模型评估分值。
- 中间展示关键特征标签，如“双向流 / 有证书 / 握手异常”。
- 右侧展示关键流量指标卡，如通信次数、上行包数、下行包数、上行负载、下行负载、包长度等。
- 指标卡建议横向排列，单个卡片只展示一个核心数值。
- 评分数值应大号展示，并包含分值单位，如 `75 分`。

基本信息建议采用描述表格，字段可包括客户端 IP、客户端端口、服务端 IP、服务端端口、协议类型、网络流量、异常特征、会话时间和研判标签。每行 2–4 组字段，字段名使用浅灰底，字段值左对齐。

应用层模型评估可使用热力图和横向条形图。热力图使用主色渐变表示强弱，每个格子显示数值，图例位于图表上方，不使用强烈彩虹色或复杂 3D 效果。横向条形图排名数量建议 5–8 项，右侧展示数值。

传输层模型评估可使用雷达图 + 指标表组合。雷达图系列不超过 2–3 条，坐标维度建议 5–7 个，右侧表格展示精确指标值。

流信息区适合使用“描述表格 + 统计卡片”组合，展示支持版本、通信版本、套件数量、选择套件、源 IP、目的 IP、威胁描述、证书信息、证书有效期等。

## 5. 对比分析详情模板

适用于 AI 模型评估、算法对比、检测结果对比、评分结果对比。

```text
抽屉标题区：标题 + 关闭按钮
→ 基础信息区：时间、任务、数据集、模型名称、数量等
→ 操作区：导出详情
→ 对比分析表：维度列 + 多模型对比列
```

规则：

- 基础信息区可使用浅蓝渐变背景，弱化装饰并突出信息分组。
- 信息字段建议 2–3 列排列。
- 重要字段可使用可复制、可点击或选中态样式。
- 对比表采用横向模型对比结构，模型列宽一致。
- 最高分使用蓝色或绿色高亮，最低分使用红色浅底高亮。
- 同一行不同模型的数据必须严格横向对齐。
- 对比页重点是表格对齐与可比较性，不应使用过多图表。

## 6. 独立详情页规范

独立详情页适合承载完整业务对象的信息，通常由固定 ReturnHeader、对象摘要、分组模块、图表、表格和操作建议组成。

```text
顶部导航 / 侧边导航
→ 固定 ReturnHeader 页面标题
→ 对象摘要区
→ 标签页 / 锚点导航 / 分组导航
→ 详情内容区
→ 关联数据 / 表格 / 日志 / 空状态
```

适用场景包括风险事件详情、资产详情、模型详情、下载行为详情、安全评估详情、报告型详情、运行状态详情和消息推送详情。

## 7. 时间轴型详情页模板

适用于风险行为、事件过程、攻击链、操作记录、异常轨迹等。

```text
顶部导航 + 左侧导航
→ 固定 ReturnHeader 页面标题
→ 标题区：对象名称 + 状态标签 + 操作按钮
→ 摘要信息区
→ 风险行为时间轴
→ 时间节点卡片
→ 展开详情表格
→ 嵌套表格 / 关联记录
```

详情页不得在 `.platform-page-content` 内重新生成面包屑或替代固定 ReturnHeader 的顶层页头；对象名称、状态标签和业务操作应作为内容区内的对象摘要或模块标题出现。

规则：

- 时间轴左侧使用时间点标记。
- 每个节点使用卡片承载事件摘要。
- 关键节点可使用风险色或状态图标。
- 节点可展开查看详情表格。
- 时间线不应过度装饰，重点是过程可追溯。

## 8. 信息分组与操作规则

- 首屏必须能识别对象身份、状态和关键判断信息。
- 信息分组按用户理解路径组织，不按接口字段顺序平铺。
- 高风险操作必须二次确认。
- 关联信息应与主对象关系清晰，不应堆叠无关表格。
- 长页详情应使用标签页、锚点或分组标题降低阅读压力。
- 风险色、状态标签、评分表达必须一致。

## 9. AI 生图要求

- 详情页必须体现对象标题、状态标签、摘要信息和核心详情模块。
- 抽屉详情必须保留背景页面和遮罩关系。
- 大抽屉宽度可接近页面 80%，但不能遮挡关闭入口。
- 分析型详情可包含图表，但图表数量应克制。
- 详情页不应被生成成列表页或 Dashboard。
- 主要中文字段和标题应基本可读。

## 10. Vue / HTML 生成要求

Vue 代码必须包含对象摘要、信息分组、关联列表或操作记录、状态标签、loading、error、empty 和必要操作反馈。HTML 预览可支持标签页切换、展开收起、抽屉打开关闭、弹窗查看详情和导出/处置等基础交互。

## 11. 验收检查清单

| 检查项 | 要求 |
|---|---|
| 对象识别 | 标题、对象名称、状态、关键摘要清晰 |
| 信息结构 | 摘要、基础信息、分析区、关联记录顺序合理 |
| 抽屉体验 | 宽度、遮罩、固定标题、关闭按钮完整 |
| 分析模块 | 图表、表格、标签和评分互相支撑 |
| 时间轴 | 时间、节点、事件、展开详情清晰 |
| 操作反馈 | 处置、导出、返回、关闭、确认等反馈完整 |
| 风险表达 | 风险色、状态标签、评分表达一致 |
| 生成质量 | 文字可读，无明显乱码、变形、错位 |
