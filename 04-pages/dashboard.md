# 工作台规范
## Dashboard Standard

Keywords: dashboard, workspace, metrics, overview, backend, ai readable, html preview

本文定义后台系统中的工作台、概览页、运营看板和个人任务首页。AI 生成工作台 HTML Demo 时，应优先继承固定 HTML 母版，并遵循页面容器、组件尺寸、颜色和交互反馈规则。

## 1. 页面定位

工作台用于帮助用户快速判断当前系统状态、风险态势、待办任务和下一步行动。它不是营销首页，也不是堆满图表的数据大屏。

核心目标：

- 首屏看清关键状态。
- 快速进入高频任务。
- 暴露待处理风险、异常、审批或任务。
- 用有限图表支持判断，不用装饰性图表填充页面。

## 2. 信息结构

标准工作台结构：

```text
页面标题 / 时间范围 / 全局筛选
→ 核心指标区
→ 待办 / 风险 / 异常提醒区
→ 趋势、分布或排行图表区
→ 快捷入口 / 最近记录 / 操作建议
```

## 3. 模块优先级

| 优先级 | 内容 | 规则 |
|---|---|---|
| P0 | 风险、异常、待办、核心状态 | 首屏必须可见 |
| P1 | 核心指标、趋势、关键排行 | 支持判断和行动 |
| P2 | 快捷入口、最近记录 | 辅助效率 |
| P3 | 说明、公告、低频统计 | 不抢占首屏 |

## 4. 指标卡

- 指标卡只展示一个核心数值和必要趋势。
- 数字、单位、同比 / 环比含义必须清晰。
- 风险、成功、警告、信息状态使用标准语义色。
- 不使用大面积渐变、玻璃拟态或营销风装饰。
- 卡片数量建议 3–6 个，避免满屏碎片化。

## 5. 图表规则

- 图表必须回答业务问题，例如趋势、分布、排行、占比或异常变化。
- 图表数量克制，首屏不应堆叠过多图表。
- 图表标题、图例、单位、空状态必须完整。
- 排行图不超过 5–8 项。
- 趋势图必须有时间范围和数据点提示。
- 图表为空时展示 empty 和下一步建议。

## 6. 待办与风险区

- 待办事项需要显示数量、类型、优先级和入口。
- 高风险事项必须有醒目但克制的状态表达。
- 每条待办或风险应有明确下一步操作。
- 列表不应过长，必要时提供“查看更多”。

## 7. 快捷入口

- 快捷入口用于承载高频任务，不做装饰性图标墙。
- 每个入口文案短、动作明确。
- 入口数量建议 4–8 个。
- hover 或点击需有反馈。

## 8. HTML Demo 要求

HTML Demo 必须支持：

- 时间范围或筛选条件切换。
- 指标卡 hover 或点击反馈。
- 至少一个图表区域的 mock 数据展示。
- 图表 empty 或 error 状态。
- 待办 / 风险列表点击进入或查看。
- 快捷入口点击反馈。
- loading、empty、error、success 中的必要状态。

## 9. AI 生成禁止项

- 禁止把工作台做成营销 landing page。
- 禁止使用无业务意义的大面积装饰图形。
- 禁止堆叠过多图表导致主任务不清晰。
- 禁止指标无单位、无时间范围、无状态含义。
- 禁止只有静态视觉，没有任何可点击交互。
- 禁止把列表页错误生成成 Dashboard。

## 10. 验收清单

| 检查项 | 要求 |
|---|---|
| 页面定位 | 明确是工作台 / 概览页，而不是列表页或营销页 |
| 首屏信息 | 核心指标、待办、风险或异常入口清晰 |
| 图表克制 | 图表服务判断，标题、单位、图例完整 |
| 状态完整 | loading、empty、error、反馈状态可见 |
| 快捷入口 | 高频动作清晰，点击有反馈 |
| 预览交互 | 筛选、点击、查看更多、状态切换可验证 |

缺少任一当前业务适用项，视为工作台 HTML Demo 生成失败。
