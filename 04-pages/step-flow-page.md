# 分步流程页规范
## Step Flow Page Standard

Keywords: step flow, wizard, steps, workflow, approval, configuration, strategy, backend, ai readable, html preview

本文定义后台系统中的分步流程页，用于创建、发布、审批、配置向导、策略配置等存在明确前后顺序的任务。AI 生成分步流程页 HTML Demo 时，应优先遵循页面容器、表单录入、反馈状态和确认规则。

## 1. 适用场景

分步流程页适用于：

- 配置项较多且存在先后依赖。
- 提交前需要分阶段确认。
- 创建、发布、审批、导入、策略配置、检测配置等流程。
- 每一步有明确输入、校验和下一步动作。

不适用于普通短表单；字段较少时优先使用普通表单页或抽屉表单。

## 2. 通用结构

```text
页面标题 / 返回入口
→ 步骤条
→ 当前步骤内容区
→ 当前步骤校验与说明
→ 底部操作区：上一步 / 下一步 / 保存草稿 / 提交
→ 结果反馈
```

## 3. 步骤条规则

- 步骤数量建议 3–5 个。
- 步骤名称使用任务语言，不使用抽象编号。
- 当前步骤高亮，已完成步骤可识别。
- 不可跳转步骤禁用并说明原因。
- 步骤切换不得丢失已填写内容。

## 4. 步骤内容

每一步只承载当前阶段必须完成的信息。

| 步骤内容 | 规则 |
|---|---|
| 基础信息 | 输入对象名称、描述、类型等 |
| 参数配置 | 展示核心配置字段和说明 |
| 规则设置 | 支持条件组、阈值、策略选择 |
| 确认提交 | 汇总前面步骤，突出风险和影响范围 |
| 结果页 | 展示成功 / 失败、下一步操作和返回入口 |

## 5. 校验与流转

- 点击下一步前校验当前步骤必填项。
- 校验失败时停留当前步骤，并定位错误字段。
- 上一步不应清空当前数据。
- 提交前展示最终确认，尤其是高风险配置。
- 提交中展示 loading，避免重复提交。
- 提交成功后展示结果反馈和下一步入口。
- 提交失败后说明原因并保留数据。

## 6. 操作区

- 操作区位置稳定，建议固定在内容区底部。
- `上一步` 为辅助按钮。
- `下一步` / `提交` 为主按钮。
- `保存草稿` 按需出现，层级低于主流程按钮。
- 取消或返回时，如存在未保存内容，必须确认。

## 7. HTML Demo 要求

HTML Demo 必须支持：

- 步骤切换。
- 上一步 / 下一步。
- 当前步骤必填校验。
- 字段输入和数据保留。
- 提交 loading。
- 提交成功 / 失败结果反馈。
- 取消或返回时的未保存确认。
- 至少一个高风险提交确认。

## 8. AI 生成禁止项

- 禁止把短表单强行拆成多步。
- 禁止步骤只展示视觉状态，不能点击切换。
- 禁止下一步不做当前步骤校验。
- 禁止切换步骤后清空已填写内容。
- 禁止提交没有 loading、成功 / 失败反馈。
- 禁止高风险提交没有确认。

## 9. 验收清单

| 检查项 | 要求 |
|---|---|
| 流程定位 | 步骤任务和顺序明确 |
| 步骤条 | 当前、已完成、禁用状态可识别 |
| 内容组织 | 每一步只承载当前阶段必要信息 |
| 校验流转 | 下一步前校验，失败时定位错误 |
| 操作区 | 上一步、下一步、提交、取消层级清晰 |
| 状态反馈 | loading、success、failure、confirm 完整 |
| 预览交互 | 步骤切换、校验、提交、结果可验证 |

缺少任一当前业务适用项，视为分步流程页 HTML Demo 生成失败。
