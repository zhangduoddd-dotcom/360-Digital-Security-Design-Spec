# 分步流程页规范
## Step Flow Page Standard

Keywords: step flow, wizard, steps, workflow, approval, configuration, strategy, backend, ai readable, html preview, vue codegen

> 本文件定义后台系统中的分步流程页，用于创建、发布、审批、配置向导、策略配置等存在明确前后顺序的任务。
>
> 全局框架、页面容器、颜色、间距、组件尺寸等通用规则，应优先遵循 `03-interaction/platform-frame.md`、`03-interaction/page-container.md`、`01-foundation/tokens.md` 和 `02-components/component-size.md`。

## 1. 适用场景

分步流程页适用于：

- 创建项目。
- 发布智能体。
- 审批流程。
- 服务开通。
- 资质认证。
- 复杂策略配置。
- 多阶段任务提交。
- 分阶段规则启用。
- 多对象逐步配置。

## 2. 标准结构

```text
页面标题 / 面包屑 / 返回入口
→ 步骤条
→ 当前步骤内容区
→ 步骤内表单 / 配置 / 预览
→ 底部操作区
→ 结果反馈
```

复杂策略配置可扩展为：

```text
返回标题
→ 顶部步骤条
→ 左侧策略列表
→ 右侧当前步骤内容
→ 底部固定操作栏
```

## 3. 步骤条规则

- 建议多于 2 步、少于 5 步。
- 只有两步能完成的流程不建议使用步骤条。
- 每一步名称应结果导向，例如“填写信息”“配置权限”“确认发布”。
- 当前步骤必须高亮。
- 已完成步骤可回看，未完成步骤默认不可跳跃。
- 如果允许跳步，必须说明业务原因。
- 已完成步骤使用对勾。
- 当前步骤使用主色圆点数字。
- 未完成步骤使用灰色。
- 步骤之间使用连接线。

## 4. 单页面步骤与多页面步骤

| 类型 | 使用场景 | 规则 |
|---|---|---|
| 单页面步骤 | 需前后对照查看、步骤间关联强 | 顶部固定步骤导航，页面内滚动展示，前置步骤影响后续数据时需确认 |
| 多页面步骤 | 每一步相对独立、无需对照查看 | 每步独立页面，仅展示当前步骤内容，底部提供上一步 / 下一步 |

## 5. 操作区规则

- 第一步不展示“上一步”。
- 中间步骤展示“上一步”“下一步”。
- 最后一步展示“上一步”“提交 / 发布 / 完成”。
- 当前步骤校验未通过时，“下一步”或最终提交按钮禁用。
- 用户返回修改上一步内容，若影响后续数据，必须二次确认。
- 底部栏可固定在页面底部，避免长流程中操作入口消失。
- 主按钮为“下一步 / 提交 / 发布 / 完成”。
- 次按钮为“上一步 / 取消”。
- 可在左侧放置“存为草稿”。

## 6. 分步式策略配置页

分步式策略配置页适用于策略配置、规则启用、分阶段配置、配置向导等流程型表单。

```text
返回标题
→ 顶部步骤条
→ 左侧策略列表
→ 右侧当前步骤内容
→ 底部固定操作栏
```

### 顶部步骤条

步骤状态包括已完成、当前步骤和未开始。

规则：

- 已完成步骤使用对勾。
- 当前步骤使用主色圆点数字。
- 未完成步骤使用灰色。
- 步骤之间使用连接线。
- 步骤数量建议 3–5 个。

### 左侧策略列表

左侧策略列表可包含策略名称、完成数 / 总数、状态标签和当前选中状态。

规则：

- 当前选中策略使用主色边框或浅绿色背景。
- 策略列表可滚动。
- 数量格式如 `2/6`、`13/13`。
- 状态标签保持低饱和。

### 右侧步骤内容

右侧步骤内容可包含折叠分组、开关、复选框、输入框、警告提示条、说明文本和多个可开关配置项。

规则：

- 当前配置分组展开，其余分组可折叠。
- 分组右侧可放置开关。
- 警告提示使用浅黄色背景。
- 内容区应保持宽松，避免配置项过密。

### 底部操作栏

底部操作栏可包含存为草稿、信息提示、上一步、下一步和取消。

规则：

- 底部栏固定在页面底部。
- 主按钮为下一步。
- 上一步为次按钮。
- 存为草稿位于左侧。
- 中间可展示当前流程完成提示。

## 7. 状态与反馈

- 当前步骤必须有明确完成状态。
- 提交中展示 loading。
- 提交失败说明原因，并保留已填写内容。
- 流程完成后展示结果页或成功反馈，并提供下一步操作。
- 如果某一步存在风险配置，应展示浅黄色提示条或二次确认。
- 返回修改上一步时，必须明确是否会清空后续配置。

## 8. AI 生图要求

- 必须展示步骤条和当前步骤内容。
- 不要把所有步骤内容堆在一屏导致层级混乱。
- 步骤名称应清晰，不能使用“步骤一、步骤二”这类无业务含义命名。
- 当前步骤、已完成步骤、未完成步骤必须视觉可区分。
- 底部操作区必须清晰可见。
- 策略类步骤页应展示左侧策略列表与右侧步骤内容的关系。

## 9. Vue / HTML 生成要求

Vue 代码必须包含步骤状态、当前步骤索引、步骤校验、上一步 / 下一步 / 提交逻辑、loading、error、成功结果反馈、必要的二次确认和 mock 数据。

HTML 预览文件必须支持步骤切换、校验失败、提交 loading、成功结果、返回修改和至少一个风险提示或确认操作。

## 10. 验收检查清单

| 检查项 | 要求 |
|---|---|
| 步骤数量 | 3–5 步优先，名称具有业务含义 |
| 当前步骤 | 高亮清晰，已完成和未完成可区分 |
| 操作区 | 上一步、下一步、提交、取消等状态正确 |
| 校验反馈 | 未通过时禁止进入下一步或给出明确提示 |
| 数据保留 | 失败或返回修改时保留已填写内容 |
| 风险处理 | 影响后续数据或高风险配置有确认逻辑 |
| 预览交互 | HTML demo 可切换、校验、提交并展示结果 |
