# 分步流程页规范
## Step Flow Page Standard

Keywords: step flow, wizard, steps, workflow, approval, configuration

本文定义后台系统中的分步流程页，用于创建、发布、审批、配置向导等存在明确前后顺序的任务。

## 1. 适用场景

分步流程页适用于：

- 创建项目。
- 发布智能体。
- 审批流程。
- 服务开通。
- 资质认证。
- 复杂策略配置。
- 多阶段任务提交。

## 2. 标准结构

```text
页面标题 / 面包屑
→ 步骤条
→ 当前步骤内容区
→ 步骤内表单 / 配置 / 预览
→ 底部操作区
→ 结果反馈
```

## 3. 步骤条规则

- 建议多于 2 步、少于 5 步。
- 只有两步能完成的流程不建议使用步骤条。
- 每一步名称应结果导向，例如“填写信息”“配置权限”“确认发布”。
- 当前步骤必须高亮。
- 已完成步骤可回看，未完成步骤默认不可跳跃。
- 如果允许跳步，必须说明业务原因。

## 4. 单页面步骤与多页面步骤

| 类型 | 使用场景 | 规则 |
|---|---|---|
| 单页面步骤 | 需前后对照查看、步骤间关联强 | 顶部固定步骤导航，页面内滚动展示，前置步骤影响后续数据时需确认 |
| 多页面步骤 | 每一步相对独立、无需对照查看 | 每步独立页面，仅展示当前步骤内容，底部提供上一步 / 下一步 |

## 5. 操作区规则

- 第一步不展示“上一步”。
- 中间步骤展示“上一步”“下一步”。
- 最后一步展示“上一步”“提交 / 发布 / 完成”。
- 当前步骤校验未通过时，“下一步”或最终提交按钮禁用。
- 用户返回修改上一步内容，若影响后续数据，必须二次确认。

## 6. 状态与反馈

- 当前步骤必须有明确完成状态。
- 提交中展示 loading。
- 提交失败说明原因，并保留已填写内容。
- 流程完成后展示结果页或成功反馈，并提供下一步操作。

## 7. AI 生图要求

- 必须展示步骤条和当前步骤内容。
- 不要把所有步骤内容堆在一屏导致层级混乱。
- 步骤名称应清晰，不能使用“步骤一、步骤二”这类无业务含义命名。

## 8. Vue / HTML 生成要求

Vue 代码必须包含步骤状态、当前步骤索引、步骤校验、上一步 / 下一步 / 提交逻辑、loading 和结果反馈。HTML 预览文件必须支持步骤切换、校验失败、提交 loading 和成功结果。
