# 异常页规范
## Exception Page Standard

Keywords: exception page, empty, error, no permission, 404, 500, maintenance

本文定义后台系统中的异常页和异常状态，用于无权限、404、500、加载失败、维护中、网络不可用等场景。

## 1. 适用场景

异常页适用于：

- 无权限访问。
- 页面不存在，404。
- 服务异常，500。
- 网络不可用。
- 系统维护中。
- 加载失败。
- 当前无数据或暂无可用内容。

## 2. 标准结构

```text
插图 / 状态图标
→ 标题
→ 说明文案
→ 建议操作
```

## 3. 文案规则

| 场景 | 标题示例 | 操作建议 |
|---|---|---|
| 无权限 | 当前无权限查看该内容 | 申请权限、返回首页 |
| 404 | 页面不存在 | 返回首页、返回上一页 |
| 500 | 服务异常 | 刷新重试、联系管理员 |
| 加载失败 | 加载失败，请刷新重试 | 刷新重试 |
| 维护中 | 系统维护中 | 稍后重试 |
| 空数据 | 暂无数据 | 新建、调整筛选、刷新 |

## 4. 设计规则

- 异常页不能只展示空白。
- 标题必须说明当前问题。
- 说明文案必须说明原因或下一步。
- 如果用户可以采取行动，必须提供按钮或链接。
- 轻量空状态可嵌入卡片内部，严重异常可独立成页。
- 无权限场景不要暴露敏感资源细节。

## 5. 组件建议

Vue 代码优先使用 `a-empty`、`a-result`、`a-alert` 或业务封装异常组件。列表页空数据优先使用表格空状态，不跳转异常页。

## 6. AI 生图要求

- 异常页必须包含标题、说明和操作入口。
- 不要只生成一张插图。
- 不要使用夸张营销风格插画。
- 空状态和异常状态要与页面整体视觉风格一致。

## 7. Vue / HTML 生成要求

Vue 代码应根据异常类型选择不同标题、说明和操作按钮。HTML 预览文件应至少模拟一种异常状态和一种可恢复操作，例如刷新重试或返回首页。
