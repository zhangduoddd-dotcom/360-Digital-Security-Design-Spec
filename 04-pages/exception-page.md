# 异常页规范
## Exception Page Standard

Keywords: exception page, empty, error, no permission, 404, 500, maintenance, html preview

本文定义后台系统中的异常页和异常状态，用于无权限、404、500、加载失败、维护中、网络不可用等场景。AI 生成异常页 HTML Demo 时，必须提供清晰原因、恢复入口和状态反馈。

## 1. 适用场景

异常页适用于：

- 无权限访问。
- 页面不存在。
- 服务异常。
- 网络不可用。
- 系统维护中。
- 数据加载失败。
- 空数据或无搜索结果（局部异常优先使用组件内空状态）。

## 2. 页面类型

| 类型 | 场景 | 主要动作 |
|---|---|---|
| 403 无权限 | 用户无访问权限 | 申请权限 / 返回首页 |
| 404 不存在 | 路由或资源不存在 | 返回首页 / 返回上一页 |
| 500 服务异常 | 服务端错误 | 刷新重试 / 联系管理员 |
| 维护中 | 系统升级或维护 | 查看公告 / 稍后重试 |
| 网络异常 | 请求失败或网络断开 | 重新加载 |
| 空状态 | 当前模块暂无数据 | 新建 / 调整筛选 / 返回 |

## 3. 信息结构

```text
异常图形 / 状态图标
→ 异常标题
→ 原因说明
→ 主要恢复操作
→ 次要辅助操作
```

规则：

- 标题直接说明当前状态，不写模糊文案。
- 说明文字解释原因和下一步建议。
- 主操作必须指向可恢复路径。
- 局部异常优先在当前模块内展示，不整页打断。

## 4. 视觉规则

- 异常页保持克制，不使用营销式插画。
- 图形或图标只用于辅助识别，不抢占主体信息。
- 文字层级清晰：标题 > 说明 > 操作。
- 主按钮只保留一个，次要操作用辅助按钮或链接。
- 空状态不使用强风险色，错误和无权限按语义色表达。

## 5. 交互规则

- 刷新重试必须有 loading 和结果反馈。
- 申请权限应打开申请入口或展示申请成功反馈。
- 返回首页 / 返回上一页必须可点击。
- 维护中可展示预计恢复时间或公告入口。
- 搜索无结果应提供清空筛选或调整条件入口。

## 6. HTML Demo 要求

HTML Demo 至少模拟一种异常状态和一种可恢复操作，例如：

- 500 错误 + 刷新重试。
- 403 无权限 + 申请权限。
- 空状态 + 新建或清空筛选。
- 网络异常 + 重新加载。

必须包含 loading、成功或失败反馈中的必要状态。

## 7. AI 生成禁止项

- 禁止只有大图，没有清晰标题和操作。
- 禁止异常页没有恢复路径。
- 禁止局部空状态直接做成整页异常。
- 禁止所有异常都使用同一种文案。
- 禁止刷新重试没有 loading 或反馈。

## 8. 验收清单

| 检查项 | 要求 |
|---|---|
| 异常类型 | 无权限、404、500、维护、网络或空状态明确 |
| 原因说明 | 文案解释当前问题和下一步建议 |
| 恢复操作 | 主操作可点击且路径清晰 |
| 状态反馈 | 重试、申请、返回等操作有反馈 |
| 视觉克制 | 图形辅助识别，不喧宾夺主 |
| 场景匹配 | 局部异常不误做整页异常 |

缺少任一当前业务适用项，视为异常页 HTML Demo 生成失败。
