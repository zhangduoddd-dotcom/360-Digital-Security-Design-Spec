# 框架 HTML 母版调用规则

本目录只保留两套可直接复用的固定 HTML 母版，以及本说明文档。

```text
06-vue-code/templates/
├── README.md
├── common-single-nav.html   # 默认 / 单层导航框架
└── double-nav-frame.html    # 双层导航框架
```

核心原则：**HTML 母版是页面底座，不是参考稿。生成页面时必须先完整复制对应 HTML 母版，再替换业务内容。**

---

## 1. 模板调用规则

| 用户描述 | 必须调用 |
|---|---|
| 基于本套 GitHub 生成页面 / 按本仓库规范生成页面 / 未明确指定导航框架 | `06-vue-code/templates/common-single-nav.html` |
| 明确说“基于单层导航框架 / 单层顶部导航 / 单层导航页面” | `06-vue-code/templates/common-single-nav.html` |
| 明确说“基于双层导航框架 / 双层顶部导航 / 双层导航页面” | `06-vue-code/templates/double-nav-frame.html` |
| 明确要求自定义导航框架 | 按用户指定方案处理 |

判断优先级：

```text
1. 用户明确要求自定义导航框架 → 按用户指定方案处理
2. 用户明确要求双层导航框架 → 使用 double-nav-frame.html
3. 用户明确要求单层导航框架 → 使用 common-single-nav.html
4. 用户只说“基于本套 GitHub / 本仓库规范 / 本套设计规范” → 默认使用 common-single-nav.html
5. 用户没有说明导航框架 → 默认使用 common-single-nav.html
```

## 2. 默认 / 单层导航框架

默认调用：

```text
06-vue-code/templates/common-single-nav.html
```

触发场景：

```text
基于本套 GitHub 生成页面
基于本仓库规范生成页面
使用本套设计规范生成页面
基于单层导航框架
基于单层顶部导航
单层导航页面
单层顶部导航页面
未明确指定导航框架
```

使用规则：

```text
1. 读取 common-single-nav.html。
2. 完整复制 common-single-nav.html 作为页面底座。
3. 只替换业务内容和 mock 数据。
4. 不重新推导、不重新拼装、不重写框架结构。
5. 保留母版中的 DOM、CSS、JS、iconfont、hover、active、open、展开收起和响应式交互。
```

## 3. 双层导航框架

明确指定双层导航时调用：

```text
06-vue-code/templates/double-nav-frame.html
```

触发场景：

```text
基于双层导航框架
基于双层顶部导航
双层导航页面
双层顶部导航页面
double-nav-frame
double top navigation
```

使用规则：

```text
1. 读取 double-nav-frame.html。
2. 完整复制 double-nav-frame.html 作为页面底座。
3. 只替换业务内容和 mock 数据。
4. 不重新推导、不重新拼装、不沿用其他旧框架。
5. 保留母版中的 DOM、CSS、JS、iconfont、hover、active、open、展开收起和响应式交互。
```

## 4. 可变内容范围

以下内容允许根据业务页面替换：

| 区域 | 可变内容 |
|---|---|
| Logo 区 | Logo 图片、Logo 文案、产品名称 |
| 顶部导航 | 导航名称、导航数量、路由含义、选中项、下拉菜单业务文案 |
| 顶部右侧信息区 | 用户名、组织名称、订阅天数、订阅数量、业务状态数据 |
| 左侧菜单 | 一级 / 二级 / 三级菜单文案、菜单数量、路由含义、默认展开项、默认选中叶子节点 |
| 页头区 | 页面标题、返回文案、页头右侧业务按钮、面包屑或页签文案 |
| 内容区 | 页面主体业务内容、列表 / 表单 / 详情 / 工作台 / 异常页等具体模块 |
| Mock 数据 | 表格数据、图表数据、卡片数据、状态数据、筛选项、分页数据 |
| 业务弹窗 / 抽屉 | 业务字段、说明文案、确认文案、示例数据 |
| 业务图标 | 有明确语义时可按 `02-components/icon.md` 替换；无明确语义时使用规范占位 icon |

要求：

```text
业务内容必须写入母版指定的业务内容区。
替换业务内容时，不得破坏固定框架结构。
菜单数据可以替换，但菜单交互规则不能替换。
按钮文案可以替换，但按钮尺寸、状态和样式规则不能替换。
```

## 5. 不可变内容范围

以下内容属于框架底座，默认不可修改：

| 区域 | 不可变内容 |
|---|---|
| HTML 基础结构 | 页面外层容器、顶部导航容器、左侧菜单容器、页头容器、内容容器的层级关系 |
| 顶部导航 | 高度、背景色、布局方式、hover / active / open 状态、下拉展开方式、右侧区域对齐方式 |
| 左侧菜单 | 宽度、收起宽度、缩进规则、icon 尺寸、hover / active / disabled 状态、展开收起逻辑、收起态级联浮层 |
| 页头区 | 页头高度、左右结构、标题层级、与内容区的上下关系 |
| 内容区 | 外层 padding、背景色、滚动规则、最小宽度和自适应逻辑 |
| Iconfont | 字体族、Font Class 使用方式、状态 icon 规则，不允许 CSS 自绘或 emoji 替代 |
| 字体渲染 | 字体栈、抗锯齿、禁止伪粗体 / 伪斜体的规则 |
| CSS 变量 / Token | 品牌色、间距、圆角、边框、阴影、控件高度等基础 Token |
| JS 交互 | 导航展开收起、菜单联级浮层、下拉显示隐藏、选中状态同步、响应式处理 |

禁止行为：

```text
不允许重新写一套顶部导航。
不允许重新写一套左侧菜单。
不允许为了“代码更简洁”删除母版 JS。
不允许为了“视觉优化”调整框架高度、宽度、间距和颜色。
不允许把双层导航和单层导航结构混合使用。
不允许把业务内容写到顶部导航、左侧菜单或页头固定结构之外。
不允许用图片、emoji、CSS 形状替代规范 iconfont。
```

## 6. 业务内容替换流程

生成页面时按以下顺序执行：

```text
1. 判断用户是否指定导航框架。
2. 读取并完整复制对应 HTML 母版。
3. 找到母版中的业务内容区。
4. 替换 Logo、导航文案、左侧菜单文案、页头文案和页面主体内容。
5. 根据页面类型补充列表、表单、详情、工作台、流程或异常态交互。
6. 保留母版原有 CSS / JS / iconfont / 响应式规则。
7. 输出单文件、可直接打开的 HTML。
```

如果需要生成 Vue 代码，也必须先保证 Vue 页面结构与所调用 HTML 母版保持一致。

---

## 7. 输出前自检

输出前必须检查：

```text
是否调用了正确母版？
是否完整保留母版 DOM、CSS、JS？
是否只替换了允许变化的业务内容？
是否误改顶部导航高度、左侧菜单宽度或页头结构？
是否保留 hover / active / open / disabled / collapsed 状态？
是否保留左侧菜单收起态和级联浮层交互？
是否使用规范 iconfont，而不是自造 icon？
是否出现旧路径、旧框架或不存在的模板引用？
```

## 8. 冲突处理

如果 README、INDEX、preview-html.md 或其他文字规范与 HTML 母版存在差异：

```text
以 HTML 母版为准。
```

如果用户要求与母版固定结构冲突：

```text
优先说明冲突点。
仅在用户明确确认“自定义导航框架”后，才允许脱离默认母版。
```

如果用户没有明确说“双层导航”或“自定义导航”：

```text
一律使用 common-single-nav.html。
```
