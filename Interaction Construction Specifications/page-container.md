# 后台管理系统页面容器搭建规范
## Background Management System Page Container Rules

Keywords: background system, page construction, layout structure, top navigation, sidebar, content container, html demo

本文定义后台管理系统页面的基础容器结构。AI 生成页面 HTML Demo 或 HTML 预览文件时，必须遵循「顶部导航栏 + 左侧边栏 + 主内容区」的三层嵌套结构，并优先继承指定 HTML 母版。

## 1. 整体结构

标准后台页面采用：

```text
全屏外层容器
→ 顶部单行导航栏
→ 下方主体区域
   → 左侧边栏
   → 主内容区
```

整体使用 Flex 水平 + 垂直嵌套布局。业务内容只允许进入母版指定的业务内容区。

## 2. 三大容器

| 模块 | 尺寸 / 定位 | 容器规则 |
|---|---|---|
| 顶部导航栏 | 高度固定 56px，宽度 100% | 深色背景，左侧品牌区，中间状态信息，右侧用户与功能区 |
| 左侧边栏 | 展开 184px，收起 56px，高度 100% | 白色背景，垂直菜单，支持二级选中和收起态浮层 |
| 主内容区 | 剩余宽高自适应 | 承载页面标题区、内容容器和业务模块 |

## 3. 顶部导航栏

顶部导航栏必须：

- 高度固定 56px。
- 宽度 100%。
- 内部元素垂直居中。
- 保持品牌、状态、功能、用户区的稳定位置。
- 不随业务内容变化挤压变形。

典型结构：

| 区域 | 内容 |
|---|---|
| 左侧 | Logo + 系统名称 + 本级中心下拉 |
| 中间 | 安全状态或运行状态提示 |
| 右侧 | 可视化入口、通知、设置、安全入口、用户头像 / 账号下拉 |

## 4. 左侧边栏

左侧边栏必须：

- 展开宽度固定 184px。
- 收起宽度固定 56px。
- 高度 100%。
- 使用白色背景。
- 支持垂直导航菜单。
- 支持当前菜单高亮。
- 支持收起态图标和级联浮层。
- 底部可固定版本号或辅助信息。

## 5. 主内容区

主内容区内部按以下结构排列：

```text
页面标题区
→ 内容容器
→ 业务子容器 / 业务模块
```

| 项目 | 规则 |
|---|---|
| 页面标题区 | 高度建议 48px，展示页面标题、返回入口、页级操作等 |
| 内容容器背景 | #F2F3F5 |
| 内容容器内边距 | 16px |
| 业务子容器背景 | #FFFFFF |
| 业务子容器内边距 | 24px |
| 业务子容器圆角 | 8px |
| 业务子容器间距 | 16px |

页面标题应清晰表达当前对象和任务。页面级主操作可放在标题区右侧。

## 6. 页面类型组合

| 页面类型 | 主内容区业务子容器内常见组合 |
|---|---|
| 列表页 | 搜索区 + 工具栏 + 表格 + 分页 |
| 详情页 | 摘要区 + 信息分组 + 关联列表 / 操作记录 |
| 表单页 | 表单区 + 操作区 |
| 工作台 | 指标区 + 待办 / 风险区 + 图表 / 快捷入口 |

## 7. 响应式与滚动

- 顶部导航栏和左侧边栏尺寸固定，不随窗口缩放改变自身规格。
- 主内容区自适应窗口宽度。
- 主内容区内容过宽时显示水平滚动条。
- 顶部和侧边容器在横向滚动时不变形。
- 小屏或窄屏下，侧边栏可收起为 56px 图标态。

## 8. 弹窗与抽屉

弹窗、抽屉、浮层属于内容弹层，不替代主内容区。AI 生成页面时，应根据任务复杂度、内容规模和用户操作成本，合理选择弹窗或抽屉。

### 8.1 使用原则

- 高风险确认优先使用弹窗。
- 详情查看、轻量编辑、筛选配置、复杂配置优先使用抽屉。
- 弹窗和抽屉必须有明确标题。
- 关闭前如有未保存内容，应提示用户确认。
- 弹层不应遮挡关键确认文案和主要操作按钮。

### 8.2 弹窗使用规范

轻量配置、简单确认、少量信息补充可使用弹窗。

弹窗适用场景：

- 配置项数量较少，建议 **5 个及以内**。
- 表单结构简单，无复杂分组、步骤、表格或长内容。
- 用户完成任务所需时间较短。
- 不需要在弹层内承载大量上下文信息。

弹窗交互规则：

- 弹窗默认居中展示。
- 必须支持右上角关闭按钮。
- 必须支持遮罩点击关闭。
- 必须保留基础滚动能力，避免小屏或极端内容溢出。
- 不建议在弹窗中出现明显滚动；如内容较多，应优先改用右侧抽屉。
- 弹窗底部操作区应固定展示，主按钮和次按钮位置稳定。

### 8.3 抽屉使用规范

当内容较多、配置项较复杂、需要承载上下文信息或需要连续查看 / 编辑时，应优先使用抽屉。

抽屉适用场景：

- 配置项超过 5 个。
- 存在多分组表单、长说明、详情信息、操作记录或关联列表。
- 用户需要边查看页面上下文，边完成局部编辑或配置。
- 弹窗高度容易超出屏幕，或需要明显滚动时。

抽屉方向规则：

- 如无明确业务要求，抽屉统一从右侧滑出。
- 如有明确场景要求，可使用其他方向，但必须在需求中说明原因。
- 不得在同一系统中随意混用不同方向的抽屉。

抽屉尺寸规则：

| 抽屉尺寸 | 适用场景 |
|---|---|
| 560px | 轻量详情、简单编辑、少量配置 |
| 880px | 中等复杂表单、多分组信息、详情 + 操作区 |
| 80% 动态宽度 | 复杂详情、大量字段、关联表格、需要更大阅读和操作空间的场景 |

尺寸选择要求：

- 默认优先使用 560px 或 880px。
- 仅当内容复杂、字段较多或包含表格时，才使用 80% 动态宽度。
- 80% 抽屉应根据实际屏幕宽度自适应，避免在小屏下挤压主要内容。
- 抽屉内部应保留滚动能力，底部操作区应固定，避免用户滚动后找不到操作按钮。

## 9. HTML Demo 要求

HTML Demo 必须能直接看出后台页面框架：

```text
顶部导航栏
+ 左侧边栏
+ 页面标题区
+ 内容容器
+ 业务子容器
```

必须优先继承固定 HTML 母版，不要只展示孤立表格、孤立表单或孤立卡片。

## 10. AI 生成禁止项

- 禁止缺少顶部导航栏。
- 禁止缺少左侧边栏。
- 禁止把主内容区做成纯白无层级页面。
- 禁止内容容器没有灰色背景和白色业务子容器。
- 禁止侧边栏宽度随内容随机变化。
- 禁止页面标题区高度和层级不稳定。
- 禁止只生成组件，不生成完整页面框架。

缺少任一框架关键结构，视为页面容器生成失败。
