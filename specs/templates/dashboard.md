# Dashboard 工作台模板
## Dashboard Template
Keywords: dashboard, homepage, overview, statistics

## Dashboard / 工作台页面模板规范

Dashboard / 工作台用于承载企业级系统的整体态势、核心指标、趋势分析、风险告警、任务待办和明细入口。页面应遵循“先概览、再诊断、后行动”的阅读路径，优先保证数据可信、层级清晰和操作明确。

### 通用页面骨架

```text
顶部全局导航
左侧一级 / 二级导航
页面标题区 / 面包屑 / 时间筛选 / 刷新操作
核心概览区
风险告警 / 状态摘要区
图表分析区
排行 / 分布 / 趋势区
明细表格 / 任务列表 / 事件列表
分页 / 辅助操作区
```

| 区域 | 规范 |
|---|---|
| 顶部导航 | 固定在页面顶部，深色背景优先，承载产品 Logo、一级导航、全局状态、通知、用户入口 |
| 左侧导航 | 白色或浅灰背景，当前项使用主色竖条与浅绿色选中底色，支持展开 / 收起 / 二级菜单 |
| 内容背景 | 使用浅灰背景，卡片使用白色底，模块之间通过 16px / 24px 间距区分 |
| 页面标题区 | 标题左对齐，时间筛选、刷新、搜索等操作右对齐 |
| 卡片容器 | 白底、弱边框或轻投影，圆角 4px / 6px / 8px，内边距 16px / 20px / 24px |
| 数据模块 | 核心指标优先放在首屏上方，图表放在中部，表格和明细放在下方 |
| 视觉重心 | 重要数值、风险、异常、AI 评分或中心图表作为首屏视觉焦点 |
| 滚动方式 | 单屏 Dashboard 使用 16:9；长页工作台可采用 1440px 宽度与自适应页面高度 |

### 顶部导航与侧边栏规范

#### 顶部导航

- 顶部导航高度建议 56px。
- 背景使用深色中性底，文字使用白色或浅灰。
- 一级导航横向排列，当前项使用主色下划线或主色高亮。
- 右侧放置系统运行状态、订阅信息、通知、帮助、用户身份与下拉入口。
- 顶部导航不承载过多业务筛选条件，业务筛选应放入内容区或二级标签区。

#### 侧边栏

- 展开态侧边栏建议 184px。
- 收起态侧边栏建议 56px。
- 当前菜单项使用浅绿色背景 + 主色竖条 + 主色文字。
- 二级菜单缩进显示，父级菜单使用展开 / 收起箭头。
- 菜单图标保持线性、轻量、统一描边。
- 页面底部可放置版本号、折叠菜单入口或系统辅助信息。

### 页面顶部工具区规范

页面顶部工具区用于承载当前页面标题、范围筛选和高频操作。

| 元素 | 规范 |
|---|---|
| 页面标题 | 4–12 字，字号 16px / 18px，字重 500 / 600 |
| 时间筛选 | 优先放在右侧，高度 32px，支持近 7 天、近 30 天、自定义时间范围 |
| 刷新按钮 | 位于时间筛选附近，使用次按钮样式 |
| 搜索框 | 可用于资产、IP、域名、事件、任务检索，高度 32px |
| 筛选器 | 单行不超过 4 个，复杂筛选放入展开面板 |
| 二级标签 | 用于切换二级模块、分类看板或数据维度，当前项使用主色下划线 |

### 核心指标卡片规范

核心指标卡用于快速呈现系统最重要的数量、比例、趋势和风险状态。

```text
图标 / 状态角标
指标标题
核心数值 + 单位
趋势箭头 / 同比环比 / 状态说明
```

| 项目 | 规范 |
|---|---|
| 单屏数量 | 4–8 个 |
| 卡片高度 | 80px / 96px / 120px |
| 图标容器 | 40px / 48px，浅色底，主色图标 |
| 指标标题 | 12px / 14px，中性色 |
| 核心数值 | 24px / 28px / 32px，深色，高字重 |
| 单位 | 放在数值右侧，字号低一级 |
| 趋势 | 上升使用绿色，下跌或风险使用红色 / 橙色 |
| 分隔方式 | 横向指标卡之间可使用竖向分割线或独立卡片间距 |

指标卡应避免堆叠长句。每张卡只表达一个核心指标。

### 风险告警与状态摘要规范

风险告警区用于突出异常、风险、告警、待处理事项和系统健康状态。

#### 风险告警条

```text
警告图标
风险摘要文案
关键风险数量
辅助指标
主操作按钮
```

- 风险告警条应靠近首屏上方。
- 高危风险使用红色或橙红色强调，背景使用浅红 / 浅橙色。
- 风险文案应包含数量和风险等级，例如“存在高危风险 33 分”。
- 主操作按钮用于“立即体检”“查看详情”“处理风险”等直接行动。
- 告警条不宜承载复杂表格，只表达核心风险与行动入口。

#### 状态摘要区

- 可采用三列结构：安全状态、风险资产、安全运维。
- 每列包含图标、指标名称、数量与单位。
- 状态类数据应使用成功、警告、错误、风险等级色区分。
- 事件类区域可使用标签页切换：安全事件 / 威胁告警 / 任务动态。

### 图表区布局规范

Dashboard 图表区应根据数据关系选择布局，不应为了填充页面而堆叠图表。

| 图表区类型 | 推荐布局 | 使用场景 |
|---|---|---|
| 两列图表区 | 1:1 或 2:1 | 趋势 + 占比、排名 + 分布 |
| 三列图表区 | 4:4:4 | 多个同级指标对比 |
| 主图 + 辅图 | 8:4 或 9:3 | 核心趋势 + 辅助分布 |
| 卡片网格 | 3 / 4 列等宽 | 监控状态、资源卡片、趋势小图 |
| 长页分析区 | 按主题纵向分区 | 安全运营、资源监控、资产盘点 |
| 全宽趋势区 | 12 栅格 | 时间跨度较长、数据点较多的趋势分析 |
| 全宽表格区 | 12 栅格 | 明细数据、事件列表、监控记录 |

### 图表类型组合规范

| 数据目标 | 推荐图表 | 展示规则 |
|---|---|---|
| 总体评分 | 仪表盘 / 环形进度 / 中心大数值 | 可作为首屏视觉中心 |
| 趋势变化 | 折线图 / 面积图 | 适合流量、风险、事件、使用率变化 |
| 类别占比 | 环形图 / 饼图 | 中心可放总数，右侧放图例 |
| Top 排名 | 横向条形图 | 用于漏洞 Top、病毒 Top、攻击来源 Top |
| 设备状态 | 进度条 / 横向排行 / 环形图 | 展示在线率、设备类型、容量占用 |
| 风险分布 | 环形图 / 分级柱状图 | 使用高 / 中 / 低风险色彩映射 |
| 能力覆盖 | 雷达图 | 用于防护能力、检测能力、技术维度对比 |
| 矩阵分析 | 热力矩阵 / 分组网格 | 用于策略覆盖、防护效果、攻击面分布 |
| 明细记录 | 表格 | 放在页面下方，支持排序、分页和详情入口 |

单屏图表类型不宜超过 3 种。长页 Dashboard 可按主题分区使用更多图表类型，但每个分区内部应保持视觉一致。

### Dashboard 页面类型模板

#### 综合态势工作台

用于展示企业、项目、系统或安全业务的整体运行状态。

```text
顶部导航
侧边栏
企业 / 项目概览横幅
关键指标总览
风险告警条
安全状态与事件摘要
资产盘点模块
运营看板模块
服务资源模块
```

必备模块：

- 企业 / 项目名称与授权状态。
- 3–5 个核心待办 / 待处理 / 待施工 / 待评估指标。
- 风险告警条，包含风险数量、风险等级和处理入口。
- 安全状态检测或健康度摘要。
- 安全事件 / 威胁告警 / 任务动态标签区。
- 资产盘点模块，包含终端统计、设备概况、设备类型分布。
- 运营分析模块，包含类型分布、Top 排名、趋势曲线。
- 服务资源模块，包含 CPU / 内存 / 磁盘 / 容量占用等资源指标。

生成约束：

- 首屏必须突出风险或待办，不要只展示普通图表。
- 长页内容应按“概览—风险—资产—运营—资源”纵向排列。
- 每个大分区必须有清晰标题。
- 图表和事件列表应保持 6:4 或 1:1 的视觉平衡。

#### 实时监控 Dashboard

用于展示系统、组件、设备或服务的实时状态。

```text
顶部导航
二级标签栏
刷新按钮
状态总览卡
组件拓扑 / 状态关系图
实时趋势图
容量与排行卡片
监控明细表格
```

必备模块：

- 总体状态卡，展示运行时长、异常状态或健康度。
- 组件状态图，中心为核心组件，周围为正常 / 异常节点。
- 最近 5 分钟或最近 10 分钟趋势图。
- 容量卡片，展示已用容量、剩余容量、磁盘列表。
- Top 排名卡片，展示数据源、设备、任务或资源排行。
- 底部监控表格，展示名称、类型、状态、分片、目录、更新时间等字段。

生成约束：

- 卡片网格优先采用 3 列或 4 列布局。
- 实时监控类图表应显示时间轴与单位。
- 正常节点使用绿色，异常节点使用红色，告警节点使用橙色。
- 底部明细表格应横跨全宽。

#### AI 决策分析 Dashboard

用于展示 AI 检测、风险判断、决策评分和策略建议。

```text
顶部导航
页面标题与时间范围
AI 决策评分英雄区
检测能力指标
风险总数与风险等级
AI 决策建议
趋势柱状图
指标摘要卡
分析图表区
分项分析标签页
```

必备模块：

- 中央大号评分，例如 80 分、92 分、A级等。
- 评分周围展示检测项、识别项、风险项、工具项等能力指标。
- 左侧展示流量、峰值、处理量等基础指标。
- 右侧展示事件总数、高风险、中风险、低风险数量。
- 中部展示 AI 决策建议或策略更新提醒。
- 下方展示柱状趋势、折线趋势、环形占比、Top 排名。
- 分项分析使用标签页，例如证书安全分析、协议分析、异常分析。

生成约束：

- AI 决策区可使用浅蓝渐变背景，但不得过度发光。
- AI 评分是首屏视觉中心，字号应明显大于其他数值。
- AI 建议必须配合人工确认或查看入口。
- 风险等级必须使用固定色彩映射：高危红色、中危橙色、低危黄色或绿色。

#### 防护分析 / 能力矩阵 Dashboard

用于展示防护覆盖、风险类型、策略执行和安全能力矩阵。

```text
顶部导航
侧边栏
筛选工具条
指标卡片条
防护能力摘要
排行条形图
趋势图 / 雷达图 / 标签云
风险明细表格
防护效果矩阵
```

必备模块：

- 顶部筛选区包含时间、类型、关键词搜索、查询和重置按钮。
- 指标卡片条展示总量、检测量、占比、防护率等。
- 防护能力模块可使用卡片、流程箭头或能力节点表达。
- 排名模块使用横向进度条或条形图。
- 标签云用于展示攻击类型、漏洞家族、风险关键词。
- 表格用于展示设备、漏洞、事件或策略明细。
- 矩阵用于展示不同对象在多个维度下的防护结果。

生成约束：

- 分析类页面允许信息密度略高，但每个模块必须有清晰边界。
- 表格与矩阵区域应置于页面下半部分。
- 矩阵颜色应使用低饱和风险色，不使用刺眼高饱和色块。
- 不使用厚重黑色分割线，模块之间使用浅灰背景间距区隔。

#### 通用数据分析 Dashboard

用于通用业务分析、运营统计、数据报表和管理后台首页。

```text
顶部导航
侧边栏
筛选区
指标卡片区
双列图表区
全宽趋势图
数据表格
分页
```

必备模块：

- 筛选区包含 2–4 个选择器、搜索框、搜索按钮、重置按钮。
- 指标卡片区包含 4 个核心指标，图标 + 标题 + 数值。
- 双列图表区包含一个占比图与一个趋势图。
- 全宽趋势图用于展示长期或细粒度变化。
- 表格展示明细数据，底部包含分页和每页条数选择。

生成约束：

- 页面结构应克制，避免过多装饰。
- 图表标题、图例、tooltip、坐标轴应清晰可读。
- 表格列数控制在 6–8 列，行数控制在 8–10 行。
- 分页置于表格右下方或底部居中偏右区域。

### 安全类 Dashboard 内容字段规范

| 模块 | 推荐字段 |
|---|---|
| 风险概览 | 风险总数、高危数量、中危数量、低危数量、待处理数量 |
| 安全事件 | 事件名称、风险等级、事件类型、处理状态、发生时间、责任人 |
| 资产盘点 | 设备总数、在线数量、在线率、设备类型、操作系统、客户端安装率 |
| 漏洞分析 | 漏洞名称、CVE 编号、影响资产、执行次数、防护率、处置状态 |
| 威胁分析 | 病毒类型、攻击来源、攻击成功告警、拦截次数、清除结果 |
| 资源监控 | CPU 占用率、内存占用率、磁盘占用率、服务状态、运行时长 |
| AI 决策 | 综合评分、检测项、识别项、风险项、策略建议、人工确认入口 |

### Dashboard 色彩与状态映射

| 含义 | 推荐颜色规则 |
|---|---|
| 主色 / 正常 / 安全 | 科技绿 `#00AB7A` 及其浅色背景 |
| 趋势辅助线 | 蓝色、绿色、橙色按数据系列区分 |
| 高危 / 严重 | 红色系，配浅红背景 |
| 中危 / 警告 | 橙色系，配浅橙背景 |
| 低危 / 提醒 | 黄色系或浅绿色系 |
| 禁用 / 无数据 | 灰色系 |
| AI 能力入口 | 蓝—青—绿色渐变，仅用于 AI 按钮、AI 评分、AI 建议入口 |

风险等级、任务状态、设备状态在同一套 Dashboard 中必须保持颜色含义一致。

### Dashboard 文案与假数据规范

| 类型 | 示例 |
|---|---|
| 页面标题 | 工作台、分析总览、安全运营看板、服务资源看板 |
| 时间范围 | 最近 7 天、最近 30 天、2023-08-11 00:00 ~ 2023-08-11 23:59 |
| 风险提示 | 距上次评估已有 0 天，安全体检综合分数 33 分，存在高危风险 |
| 操作按钮 | 立即体检、查看详情、刷新、搜索、重置、导出 |
| 事件状态 | 高危、处理中、已修复、请验收、添加信任 |
| 设备状态 | 在线、离线、正常、异常、待处理 |
| 数据单位 | 个、台、次、条、GB、MB/s、KB/s、% |
| 表格操作 | 详情、编辑、处置、忽略、更多 |

数值展示应包含单位，不应只出现孤立数字。大数值可使用千分位或“万”作为单位。

### Dashboard AI 生图 Prompt 模板

#### 综合态势工作台 Prompt

```text
生成一张企业级安全态势工作台 Dashboard 高保真界面效果图，简体中文，16:9，4K，正视角平面 UI。页面包含深色顶部导航、浅色左侧导航、右侧主内容区。主内容区从上到下包括：企业信息概览横幅、待办指标、风险告警条、安全状态检测、安全事件列表、资产盘点、运营分析图表、服务资源仪表盘。视觉风格为浅色科技商务风，白色卡片、冷灰背景、科技绿主色，风险使用红色和橙色，AI 能力入口使用蓝—青—绿色渐变。图表包含环形图、横向排名条、折线趋势图和资源仪表盘，文字和数值清晰可读，布局专业克制，不使用游戏风和过度发光效果。
```

#### 实时监控 Dashboard Prompt

```text
生成一张企业级实时监控 Dashboard 高保真界面效果图，简体中文，16:9，4K，正视角平面 UI。页面包含深色顶部导航、左侧分级导航、二级标签栏和刷新按钮。主内容区采用卡片网格布局：总体状态卡、组件状态拓扑图、最近 5 分钟使用率趋势、读写趋势、入口出口流量趋势、容量卡片、数据源排名、底部监控明细表格。卡片白底、轻投影、浅灰页面背景，正常状态用绿色，异常状态用红色，趋势线使用绿色和蓝色。整体信息密度适中，图表标题、坐标、图例和表格字段清晰可读。
```

## Dashboard 图表及多分辨率适配规范

> 适用于 Dashboard 图表页、常规内容页、抽屉、弹窗等需要在多分辨率下保持信息完整的界面。

### 适配目标

基于多产线对自适应适配问题的反馈，Dashboard 和常规页面需要建立统一的多分辨率适配规则，以提升产品在主流浏览器分辨率下的展示质量。

**适用范围：**

- 常规页面
- Dashboard 图表页
- 特殊设计页面
- 抽屉
- 弹窗
- 表格
- 异形及非常规图表

### 多分辨率页面适配

| 分辨率 | 适配逻辑 |
|---|---|
| 1920px | 左侧导航栏固定，右侧内容区域基于内容自适应 |
| 1440px | 左侧导航栏固定，右侧内容区域基于内容自适应 |
| 1366px | 左侧导航栏固定，右侧内容区域基于内容自适应 |
| 1280px | 左侧导航栏固定，右侧内容区域基于内容自适应 |

**侧边栏响应：**

- 侧边栏可设置为响应式布局。
- 浏览器宽度小于配置断点时，侧边导航自动从展开态变为收起态。
- 默认断点值为 `992px`。
- 页面最小宽度为 `768px`。
- 侧边栏收起态宽度为 `56px`。
- 内容区小于 `768px` 时，页面不再缩小，浏览器出现横向滚动条。

### Dashboard 卡片布局适配

Dashboard 采用 12 栅格布局。卡片可按照以下比例进行划分：

| 划分方式 | 适用内容 |
|---|---|
| 1 | 大型趋势图、地图、核心工作区 |
| 1/2 | 两个并列图表或左右对比 |
| 1/3 | 三个核心分析模块 |
| 1/4 | 四个指标卡片或小图表 |
| 1/5 | 五个轻量指标卡片 |
| 1/6 | 六个极简状态卡片 |
| 1/12 | 对齐辅助，不建议承载复杂内容 |

**关键原则：**

- 卡片宽度随页面宽度自适应。
- 设计时必须考虑卡片最小宽度。
- 当卡片达到最小宽度后，不应继续压缩内容。
- 宽度不足时优先换行或出现横向滚动，而不是造成信息丢失。

### 图表自适应总原则

```text
图表自适应优先级：
信息完整性 > 信息有效传达 > 页面整齐 > 强行压缩到一屏
```

**执行要求：**

- 图表必须定义最小适配宽度。
- 图表不可因容器缩小而出现标签重叠、图例丢失、坐标轴不可读。
- 当容器宽度小于图表最小宽度时，应出现横向滚动条。
- 图表适配规则不仅适用于页面，也适用于抽屉、弹窗等场景。

### 环形 / 饼图 / 玫瑰图 / 雷达图 / 仪表盘适配

| 项目 | 标准 |
|---|---|
| 适用图表 | 环形图、饼图、玫瑰图、雷达图、仪表盘 |
| 适配逻辑 | 图表区域定宽，卡片留白区域基于页面宽度自适应拉伸 |
| 宽度不足 | 小于图表定宽区域时出现横向滚动条 |
| 推荐列数 | 2 列、3 列 |
| 不推荐列数 | 1 列、4 列及更多 |

**原因：**

- 1 列场景下使用环形图容易显得内容过于松散。
- 4 列及更多列数下，图表内容拥挤，信息传达和美观性都会受影响。
- 2 列和 3 列能较好保证信息展示完整性与有效传达。

### 趋势类图表适配

| 项目 | 标准 |
|---|---|
| 适用图表 | 折线图、面积图等趋势类图表 |
| 适配逻辑 | 图表两端固定宽度，图表内容在保证显示完全的情况下基于页面宽度自适应拉伸 |
| 最小宽度 | 需要定义，避免窄宽度下图表变形或展示不全 |
| 推荐列数 | 1 列、2 列、3 列 |
| 不推荐列数 | 4 列及更多 |

**执行说明：**

- 趋势类图表通常需要横向空间表达时间序列。
- 四列及更多列数会导致图表过窄，容易造成信息展示不完整。
- 对折线图、面积图，应优先保证坐标轴、图例、数据点和趋势方向可读。

### 柱形图类图表适配

| 项目 | 标准 |
|---|---|
| 适用图表 | 柱状图、分组柱状图、柱形混合图、多柱形图、气泡图 |
| 适配逻辑 | 图表两端固定宽度，图表内容在保证显示完全的情况下基于页面宽度自适应拉伸 |
| 最小宽度 | 需要定义，避免窄宽度下柱体拥挤、标签重叠、图例丢失 |
| 推荐列数 | 优先 1 列、2 列、3 列 |
| 谨慎列数 | 4 列 |
| 不推荐列数 | 4 列以上，尤其是维度较多或分组较多时 |

**执行说明：**

- 柱形图用于比较，横向空间不足会严重影响标签阅读。
- 多柱形图、分组柱状图对空间要求更高，应减少并列列数。
- 若必须放入窄卡片，应减少维度数量或改用指标卡 / 排名列表。

### 抽屉与弹框适配规则

目前定义三类尺寸，以满足不同场景下的业务需求：

| 类型 | 宽度 | 适用场景 |
|---|---:|---|
| 小尺寸 | 560px | 简单查看、轻量编辑、确认信息 |
| 中尺寸 | 880px | 表单编辑、详情查看、多字段配置 |
| 自适应尺寸 | 屏幕宽度的 80% | 复杂配置、图表详情、批量处理、较大内容承载 |

**执行要求：**

- 抽屉和弹窗中的图表也必须遵循图表最小宽度规则。
- 内容复杂时优先使用 80% 屏幕宽度，而不是在 560px 内强行压缩。
- 弹窗/抽屉的操作区应固定在底部或顶部可见区域，避免用户滚动后找不到操作按钮。

### 表格适配规则

表格整体基于页面宽度自适应拉伸，优先缩放列表空白区域。

| 阶段 | 适配方式 |
|---|---|
| 页面宽度充足 | 表格整体随页面宽度拉伸 |
| 页面宽度缩小 | 优先压缩列之间的空白区域 |
| 空白区域消失 | 固定表头和操作列，中间区域基于屏幕宽度拉伸 |
| 仍然不足 | 表格底部出现左右横向滚动条 |
| 无多选表头 | 可取消固定表头中的多选区域 |

**强制要求：**

- 表格不能为了适配而压缩到字段不可读。
- 操作列需要优先固定，避免用户滚动后找不到操作。
- 批量选择列、关键识别列、状态列可根据业务优先级选择固定。
- 横向滚动条出现时，应确保表头与内容列对齐。

### 异形及非常规图表适配规则

异形及非常规图表由于结构特殊，不适合用单一规则机械套用，应进行宏观约束。

| 规则 | 说明 |
|---|---|
| 定义最小适配宽度 | 小于最小宽度时出现横向滚动条 |
| 基于最小宽度自适应拉伸 | 需要明确标注拉伸区域 |
| 常规拉伸方式 | 两侧留白区域或内容区进行自适应拉伸 |
| 核心原则 | 优先保证信息展示完整和有效传达 |

**设计交付要求：**

- 必须在设计稿中标注最小宽度。
- 必须标注可拉伸区域和不可拉伸区域。
- 必须说明低于最小宽度时的表现方式。
- 如果图形不可压缩，应直接定义横向滚动，而不是交给前端临时处理。
