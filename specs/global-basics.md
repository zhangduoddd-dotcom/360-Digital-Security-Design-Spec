# 全局基础规范
## Global Basic Specification
Keywords: base, style, token, layout, B-end, enterprise SaaS

> 适用对象：企业级 SaaS / B 端管理后台 / AI 原生多智能体协作平台  
> 文档目标：形成一套可直接用于 Figma 设计、AI 生图提示词、前端组件开发与设计验收的 B 端界面规范。  

---

## 规范体系总览

这套规范不是单纯的 UI 样式集合，而是一套完整的 B 端界面设计标准。它的核心结构可以理解为：

```text
设计原则
  ↓
全局样式 Token
  ↓
页面架构与响应式布局
  ↓
导航与页面组织
  ↓
基础操作组件
  ↓
数据录入组件
  ↓
数据展示组件
  ↓
反馈与异常处理
  ↓
业务场景模板与验收标准
```

### 规范核心价值

| 层级 | 作用 | 对界面落地的意义 |
|---|---|---|
| 全局样式 | 规定颜色、字体、栅格、投影、布局 | 保证不同页面看起来属于同一产品体系 |
| 页面架构 | 规定顶部、侧边栏、内容区、弹层等关系 | 保证页面结构稳定，不因业务复杂而混乱 |
| 导航组件 | 规定顶部导航、侧边导航、面包屑、标签页、步骤条 | 帮助用户理解“我在哪里、能去哪里、下一步是什么” |
| 数据录入 | 规定表单、输入框、选择器、日期时间、上传等 | 降低输入成本，减少错误 |
| 数据展示 | 规定表格、卡片、标签、统计数值、描述列表等 | 提高复杂信息的阅读效率 |
| 反馈机制 | 规定全局提示、通知、警告、抽屉、弹窗、空状态、异常页 | 让系统状态、操作结果和风险后果被用户及时理解 |
| 业务范式 | 规定删除、创建、更新、离开等敏感操作反馈模板 | 保证高风险操作的提示一致、清晰、可追责 |

### 本规范的使用方式

本规范可以用于四类场景：

1. **设计前**：作为页面架构、组件选型、信息层级的依据。
2. **设计中**：作为 Figma 组件、页面布局、交互状态的统一标准。
3. **设计后**：作为设计走查、前端验收、体验一致性检查表。
4. **AI 生成界面时**：作为提示词中的结构约束和视觉约束，避免生成结果“好看但不可用”。

## 设计原则

### 一致性

同一产品内的页面结构、组件样式、交互反馈、文案表达应保持一致。

**执行要求：**

- 同类页面使用同一布局骨架。
- 同类操作使用同一按钮层级。
- 同类状态使用同一颜色和提示方式。
- 同类表单使用同一标签、校验和帮助信息规则。
- 同类风险操作使用同一弹窗反馈模板。

### 可适配

页面应适配主流屏幕分辨率和不同信息密度场景。

**执行要求：**

- 设计输出默认以 `1440px` 画板为基准。
- 适配主流分辨率：`1920 / 1440 / 1366 / 1280`。
- 内容区域使用响应式布局。
- 栅格、卡片、表格和图表应根据视窗宽度自适应。
- 侧边栏在小屏下应支持自动收起或图标态。

### 可控性

界面需要清晰、直接、可预期，减少用户的记忆负担。

**执行要求：**

- 页面主任务必须明确。
- 一个操作区域只保留一个最重要的主按钮。
- 高风险操作必须解释后果。
- 复杂任务应拆分为步骤。
- 系统状态必须及时反馈。
- 异常、空状态、加载态不能留白或让用户猜测。

### 业务安全性

对于安全、审批、删除、断开、禁用、覆盖、重置等敏感操作，必须强化确认机制。

**执行要求：**

- 弹窗标题必须包含动作和对象。
- 描述必须说明操作后的结果。
- 高风险操作必须说明是否可恢复。
- 不可逆操作不得只用 Toast 提示。
- 操作前、操作中、操作后都应有清晰反馈。

## 全局样式规范

### 布局基准

#### 布局定义

空间布局是体系化设计的起点。页面整体布局是产品最外层的框架结构，一般包含导航、侧边栏、面包屑、内容区、弹层等。布局需要从动态、体系化的角度处理界面空间秩序，让用户在复杂 B 端任务中能够快速识别页面结构和操作路径。

布局方式决定界面元素之间的关系、韵律和节奏。对于企业级 SaaS / B 端后台 / AI 原生协作平台，布局不是装饰问题，而是信息组织、任务优先级和操作效率的问题。

#### 布局设计原则

| 原则 | 解释 | 落地要求 |
|---|---|---|
| 一致性 | 确保产品布局在结构和视觉上保持一致，为用户提供稳定、舒适的使用感 | 同类页面使用同一布局骨架；同类模块保持相同间距、卡片结构和操作区位置 |
| 可适配 | 布局应根据不同设计环境、浏览器宽度和屏幕分辨率进行响应式适配 | 支持 1920 / 1440 / 1366 / 1280 等主流分辨率；内容区随宽度变化自适应 |
| 可控性 | 页面需要简单、直白、可识别，减少用户记忆负担 | 主任务清晰；复杂功能可扩展；页面结构能随业务复杂度延展 |

#### 布局执行原则

| 项目 | 标准 |
|---|---|
| 默认设计画板 | 1440px |
| 主流适配宽度 | 1920px、1440px、1366px、1280px |
| 最小原子单位 | 4px |
| 间距计算方式 | `间距 = x × 4px` |
| 栅格体系 | 12 栅格 |
| 常见布局方式 | T 字形布局、左右布局、上下布局 |
| 内容区 | 响应式区域 |
| 设计输出原则 | 统一画板尺寸输出布局，适配方案遵循一致的响应式布局原则 |

#### 页面四层框架

根据用户操作行为进行层级区分，页面框架可分为四层。设计时应从下到上建立信息层级，避免所有内容同时争抢视觉注意力。

| 层级 | 内容 | 说明 |
|---|---|---|
| 背景区域 | 页面底色、背景纹理、全局背景 | 提供环境氛围，不承担主要信息表达 |
| 内容层 | 表格、列表、卡片、图表、表单、工作区 | 用户完成任务的主要区域 |
| 全局控制层 | 顶部导航、侧边导航、全局搜索、通知、账户入口 | 负责全局跳转、系统级操作和跨页面控制 |
| 内容弹层 | 弹窗、抽屉、气泡确认框、浮层详情 | 承载临时任务、确认、补充说明和局部编辑 |

#### 响应式布局定义

响应式布局是指在不同分辨率下，让内容以最优展示形式呈现给用户，从而提升使用体验。响应式布局系统用于调整界面结构，以适应不同屏幕分辨率和浏览器视窗大小。

**执行要求：**

- 使用基于百分比的计算，而不是完全依赖固定像素。
- 图像、卡片、图表和内容区域应可缩放。
- 通过断点控制布局切换。
- 容器可以固定，也可以根据断点流体变化；最终以设计输出要求为准。
- 当宽度小于断点临界值时，卡片宽度应基于可用宽度自适应，同时必须考虑卡片最小宽度。

#### 响应式断点与侧边栏策略

| 视窗宽度 | 栅格列数 | Gutter | Margin | 侧边栏收起动作 | 展开动作 | 展开方式 |
|---|---:|---:|---:|---|---|---|
| `< 768px` | 4 | 16px | 24px | 自动完全收起 | 点击按钮展开 | Overlay |
| `768px–991px` | 8 | 16px | 24px | 自动收起，展示图标 | 点击按钮展开 | Push |
| `992px–1199px` | 12 | 24px | 24px | 点击按钮收起，展示图标 | 点击按钮展开 | Push |
| `≥ 1200px` | 12 | 24px | 24px | 点击按钮收起，展示图标 | 点击按钮展开 | Push |

**补充规则：**

- 侧边栏区域可设置为响应式布局。
- 当浏览器宽度小于配置断点值时，侧边导航自动从展开态变为收起态。
- 默认侧边栏响应断点为 `992px`。
- 页面最小宽度定义为 `768px`。
- 收起态侧边栏宽度定义为 `56px`。
- 当内容区域小于 `768px` 时，页面不再继续缩小，浏览器应出现横向滚动条。

#### 主流分辨率适配逻辑

| 分辨率 | 适配逻辑 |
|---|---|
| 1920px | 左侧导航栏固定，右侧内容区域基于内容自适应 |
| 1440px | 左侧导航栏固定，右侧内容区域基于内容自适应 |
| 1366px | 左侧导航栏固定，右侧内容区域基于内容自适应 |
| 1280px | 左侧导航栏固定，右侧内容区域基于内容自适应 |

### 栅格系统

#### 基础规则

| 项目 | 规范 |
|---|---|
| 栅格体系 | 12 栅格 |
| 主要适用 | Dashboard、概览页、统计页、卡片流、分析页 |
| Column | 弹性布局 |
| Gutter | 16px 或 24px，常规桌面场景优先 24px |
| Margin | 常规桌面场景优先 24px |
| 盒子模型 | Border & Corner、Padding、Margin、Background、Shadow、Content、Size |

#### 卡片栅格划分

| 栅格占比 | 页面呈现 | 适用场景 |
|---|---|---|
| 1 | 一行 1 个大卡片 | 大图表、核心工作区、复杂表单 |
| 1/2 + 1/2 | 一行 2 个卡片 | 左右并列分析、双指标对比 |
| 1/3 + 1/3 + 1/3 | 一行 3 个卡片 | 常规 Dashboard 指标区 |
| 1/4 × 4 | 一行 4 个卡片 | 小型统计卡片、状态概览 |
| 1/5 × 5 | 一行 5 个卡片 | 较高密度指标展示，需谨慎控制文本量 |
| 1/6 × 6 | 一行 6 个卡片 | 极高密度状态入口，不建议承载复杂图表 |
| 1/12 × 12 | 细粒度栅格 | 仅用于布局对齐，不建议直接作为业务卡片宽度 |

#### 盒子模型

每一个卡片在前端实现时都应被视为一个盒子。盒子由以下属性构成：

```text
Box = Border & Corner + Padding + Margin + Background + Shadow + Content + Size
```

| 属性 | 含义 | 推荐标准 |
|---|---|---|
| Border & Corner | 边框与圆角 | 保持同类卡片统一 |
| Padding | 内边距 | Dashboard 卡片常规使用 24px；高密度列表可适当压缩 |
| Margin | 外边距 | 模块之间依据 12px / 16px / 24px 控制 |
| Background | 背景 | 白色或浅灰卡片背景，避免破坏数据阅读 |
| Shadow | 投影 | 轻投影，仅用于层级区分 |
| Content | 内容 | 文本、图表、表格、操作区 |
| Size | 尺寸 | 依据栅格和断点自适应 |

#### 栅格响应策略

| 断点 | 响应区间 | 推荐布局 |
|---|---|---|
| 1200px | `> 1200px` | 布局方式一：多列布局，可承载 A / B / C 等多个并列模块 |
| 992px | `992px–1199px` | 布局方式二：减少横向列数，优先保证主要模块完整 |
| 768px | `768px–991px` | 布局方式三：进一步减少列数，卡片逐步纵向堆叠 |
| `< 768px` | 小于最小页面宽度 | 不再压缩页面，出现横向滚动条 |

**强制要求：**

- 卡片宽度不能无限缩小。
- 图表类卡片必须定义最小宽度。
- 信息展示完整性优先于“强行适配一屏”。
- 页面宽度不足时，应通过换行、堆叠、横向滚动处理，而不是压缩到不可读。

#### 间距建议

| 场景 | 建议 |
|---|---|
| 页面边距 | 24px |
| 常规卡片内边距 | 24px |
| Dashboard 卡片之间 | 12px / 16px / 24px，根据密度选择 |
| 列表页卡片间距 | 优先 12px，部分卡片场景可使用 16px |
| 标题与内容 | 8px / 12px / 16px |
| 操作按钮之间 | 列表页统一 8px；非高密度页面可使用 12px |
| 模块分组之间 | 16px / 24px |


### 字体规范

#### 字体家族

优先使用系统默认界面字体，保证跨平台可读性。

```css
font-family:
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  "Helvetica Neue",
  "PingFang SC",
  "Hiragino Sans GB",
  "Microsoft YaHei UI",
  "Microsoft YaHei",
  Arial,
  sans-serif;
```

#### 字阶与行高

| 类型 | 字号 | 行高 | 字重 | 使用场景 |
|---|---:|---:|---:|---|
| 超大标题 | 48px | 54px | Bold | 大屏标题、品牌主标题 |
| 一级标题 | 28px | 36px | Bold | 页面主标题 |
| 二级标题 | 18px | 26px | Bold | 模块标题、卡片标题 |
| 头部/大按钮 | 16px | 28px | Regular / Medium | 顶部导航、重要按钮 |
| 正文 | 14px | 22px | Regular | 表格、表单、普通文本 |
| 辅助文本 | 12px | 20px | Regular | 提示、说明、标签、元信息 |

#### 字重

| 字重 | CSS 值 | 使用场景 |
|---|---:|---|
| Regular | 400 | 正文、说明、表单内容 |
| Medium | 500 | 导航选中、按钮、重点文字 |
| Bold | 600/700 | 标题、强调信息 |

### 颜色规范


#### 主色 Primary：科技绿体系

| Token | 色值 | 语义 / 使用场景 |
|---|---|---|
| `p1` | `#D9F4EE` | 部分组件选中态填充色、浅色图形化配色 |
| `p2` | `#B9F7E2` | 图形化配色、浅绿色辅助色 |
| `p3` | `#71EDC2` | 图形化配色、视觉辅助色 |
| `p4` | `#4AD3A4` | 图形化配色、进阶辅助色 |
| `p5` | `#1DB887` | 可交互控件 hover 填充色、图形化配色 |
| `p6` | `#00AB7A` | **主色 / 主按钮 normal / 可交互控件默认填充色 / 文本 hover** |
| `p7` | `#039972` | 可交互控件 click / active；文本 normal |
| `p8` | `#008563` | 文本 click / 深层交互色 |
| `p9` | `#006853` | 深色图形化配色 |
| `p10` | `#013C32` | 最深图形化配色，不建议大面积背景使用 |

#### 主色使用规则

- 普通主按钮：默认使用 `p6`，hover 使用 `p5`，active/click 使用 `p7`。
- 选中态浅底：优先使用 `p1`。
- 链接文字：常规可使用 `p7`，hover 可使用 `p6`，click 可使用 `p8`。
- 图表中可使用 `p1-p10` 形成同色系递进，但不要让深色 `p9/p10` 大面积压住页面。

#### AI 渐变色：只用于 AI 能力入口

| Token | CSS 值 | 使用场景 |
|---|---|---|
| `AI 默认` | `linear-gradient(307deg, #004DFF 0%, #1093FF 65%, #1AFFAF 100%)` | AI 主按钮默认态，如“智能生成”“AI 分析”“智能推荐” |
| `AI 悬停` | `linear-gradient(0deg, rgba(255,255,255,0.20), rgba(255,255,255,0.20)), linear-gradient(126deg, #1AFFAF 0%, #1093FF 37%, #004DFF 100%)` | AI 按钮 hover 态，叠加 20% 白色蒙层 |
| `AI 按下` | `linear-gradient(0deg, rgba(0,0,0,0.20), rgba(0,0,0,0.20)), linear-gradient(309deg, #004DFF 0%, #1093FF 54%, #1AFFAF 100%)` | AI 按钮 active/click 态，叠加 20% 黑色蒙层 |

#### AI 渐变使用边界

- 只用于 AI 能力入口、AI 生成、AI 分析、智能推荐、自动补全等“智能能力”操作。
- 不用于普通提交、保存、删除、筛选、导出等常规业务按钮。
- 同一页面 AI 渐变按钮数量应克制；如果所有按钮都用渐变，AI 入口会失去识别度。
- AI 按钮文字建议使用白色，图标使用白色或浅色线性图标。

#### 中性色 Neutral

| Token | 色值 | 语义 / 使用场景 |
|---|---|---|
| `gray-1` | `#FFFFFF` | 白色容器、卡片背景、弹窗内容区 |
| `gray-2` | `#F8F9FA` | 页面浅背景、表格表头背景、弱分区背景 |
| `gray-3` | `#F2F3F5` | 白背景 hover、浅灰页面背景 |
| `gray-4` | `#E8EAED` | 分割线、表格线、弱边界 |
| `gray-5` | `#DFE1E6` | 边框、输入框边界、次要按钮边框 |
| `gray-6` | `#AEB2B8` | 禁用态、placeholder、不可交互文本 |
| `gray-7` | `#8A9099` | 次要文字、辅助说明、默认图标色 |
| `gray-8` | `#525966` | 正文、常规信息文字 |
| `gray-9` | `#242933` | 标题、主要文字、高强调文本 |
| `gray-10` | `#000000` | 极深色，仅用于特殊强对比场景，不建议大面积使用 |

#### 中性色使用规则

- 页面背景优先使用 `gray-2` 或 `gray-3`，容器背景使用 `gray-1`。
- 正文使用 `gray-8`，标题使用 `gray-9`。
- 辅助文本、说明、时间、来源信息使用 `gray-7`。
- 禁用态和 placeholder 使用 `gray-6`。
- 分割线用 `gray-4`，边框用 `gray-5`，不要混用。

#### 功能色 Semantic Colors

| 类型 | 浅背景 | 辅助色 / 边框 | 主色 | 深色 | 使用场景 |
|---|---|---|---|---|---|
| 成功 / 完成 | `Green-1 #EFF8EE` | `Green-3 #BCE0B4` | `Green-6 #52C41A` | `Green-7 #389E0D` | 成功、完成、安全、通过 |
| 警告 / 待处理 | `Orange-1 #FFF8E6` | `Orange-4 #FFC054` | `Orange-6 #F58A02` | `Orange-7 #CF6E00` | 警告、处理中、待审核、需关注 |
| 错误 / 失败 | `Red-1 #FFE8E6` | `Red-2 #FFBEB8` / `Red-3 #FF948F` | `Red-6 #F0131E` | `Red-7 #C90616` | 失败、错误、危险操作 |

| 低强度提示 | `Yellow-1 #FFFFE6` | `Yellow-5 #EBD426` | `Yellow-6 #DFBC00` | `Yellow-7 #B89600` | 低风险提醒、轻提示、弱警示 |
| 高风险提醒 | `Orange red-1 #FFF3E6` | `Orange red-3 #FFBC85` | `Orange red-6 #F05A0A` | `Orange red-7 #C94000` | 高危、强警告、需优先处理 |
| 致命 / 极高风险 | `Deep red-1 #FCE7E3` | `Deep red-2 #F0A399` | `Deep red-6 #BC0004` | `Deep red-7 #960008` | 致命风险、严重阻断、强破坏性操作 |

#### 安全等级色映射

| 安全等级 | 推荐 Token 组合 | 使用说明 |
|---|---|---|
| 致命 | `Deep red-1 / Deep red-2 / Deep red-6 / Deep red-7` | 安全产品中的最高风险等级，必须强提示 |
| 严重 | `Red-1 / Red-3 / Red-6 / Red-7` | 严重错误、重大风险、不可忽略状态 |
| 高危 | `Orange red-1 / Orange red-3 / Orange red-6 / Orange red-7` | 高优先级风险、紧急待处理 |
| 中危 | `Orange-1 / Orange-4 / Orange-6 / Orange-7` | 中等风险、待处理、警告 |
| 低危 | `Yellow-1 / Yellow-5 / Yellow-6 / Yellow-7` | 低风险、弱警示 |
| 安全 | `Green-1 / Green-3 / Green-6 / Green-7` | 安全、通过、正常 |
| 未知 | `gray-4 / gray-6 / gray-8` | 未检测、未分类、不可判断 |

#### 状态描边 / Focus Ring

| Token | CSS 值 | 使用场景 |
|---|---|---|
| `Default 默认` | `0px 0px 0px 2px #D9F4EE` | 默认聚焦、选中、可编辑控件 focus |
| `Error 错误` | `0px 0px 0px 2px #FFE8E6` | 表单错误、校验失败、危险输入聚焦 |
| `Success 成功` | `0px 0px 0px 2px #EFF8EE` | 成功校验、通过状态聚焦 |
| `Warning 警告` | `0px 0px 0px 2px #FFF8E6` | 警告状态、待确认输入聚焦 |

#### 描边使用规则

- Focus ring 不应改变组件本体尺寸，应使用 `box-shadow` 外描边方式实现。
- 表单控件的错误态优先使用 `Error 错误` 描边，同时配合错误文案。
- 选中态、键盘聚焦态必须可见，不能只依赖颜色深浅变化。
- 不建议把 focus ring 做成过重发光，否则会破坏 B 端界面的稳定感。

#### Token 命名与重复变量处理

| 情况 | 处理规则 |
|---|---|
| `Blue-7` 重复出现，色值一致 | 保留一个标准定义即可 |
| `gray-6/7/8/9` 重复出现，色值一致 | 保留第一次定义即可 |
| `P6` 与 `p6` 一致 | 前端交付统一使用小写 `p6` |
| `P7` 与 `p7` 一致 | 前端交付统一使用小写 `p7` |
| 中文变量名如 `AI 默认`、`投影-默认` | 设计文档保留中文名；代码落地建议增加英文 alias |

### 投影规范

> 投影不是装饰，而是表达层级关系：卡片浮起用一级投影，抽屉/弹窗/遮罩浮层用二级投影，超级框 hover 使用专门阴影。

#### 一级投影：卡片与模块浮起

| Token | CSS 值 | 使用场景 |
|---|---|---|
| `一级-向上` | `0px -4px 16px 0px rgba(36,41,51,0.05)` | 顶部浮起卡片、向上投影模块 |
| `一级-向下` | `0px 4px 16px 0px rgba(36,41,51,0.05)` | 常规卡片、Dashboard 模块、白底容器浮起 |
| `一级-向右` | `4px 0px 16px 0px rgba(36,41,51,0.05)` | 左侧卡片、侧栏轻量浮起 |
| `一级-向左` | `-4px 0px 16px 0px rgba(36,41,51,0.05)` | 右侧卡片、右栏轻量浮起 |

#### 二级投影：抽屉、弹窗、遮罩浮层

| Token | CSS 值 | 使用场景 |
|---|---|---|
| `二级-向上` | `0px -8px 80px 0px rgba(36,41,51,0.08)` | 底部抽屉、底部浮层 |
| `二级-向下` | `0px 8px 80px 0px rgba(36,41,51,0.08)` | 弹窗、Popover、大型浮层 |
| `二级-向右` | `6px 0px 80px 0px rgba(36,41,51,0.08)` | 左侧抽屉、左侧浮层 |
| `二级-向左` | `-8px 0px 80px 0px rgba(36,41,51,0.08)` | 右侧抽屉、右侧浮层 |

#### 通用投影与特殊 hover 投影

| Token | CSS 值 | 使用场景 |
|---|---|---|
| `投影-默认` | `0px 3px 6px -4px rgba(0,0,0,0.12), 0px 6px 16px 0px rgba(0,0,0,0.08), 0px 9px 28px 8px rgba(0,0,0,0.04)` | 标准浮层、卡片、下拉面板默认阴影 |
| `投影-悬停` | `0px 1px 2px -2px rgba(0,0,0,0.16), 0px 3px 6px 0px rgba(0,0,0,0.12), 0px 5px 12px 4px rgba(0,0,0,0.08)` | 卡片 hover、可点击模块 hover |
| `超级框hover阴影` | `0px 4px 12px 0px rgba(183,179,255,0.50)` | AI 超级输入框、智能搜索框、AI 主输入区 hover |

#### 投影使用原则

- 卡片浮起优先使用一级投影，不要直接套用二级投影。
- 弹窗、抽屉、遮罩浮层必须明显高于普通卡片，使用二级投影。
- Dashboard 卡片可以使用 `一级-向下`，hover 时可切换为 `投影-悬停`。
- AI 超级输入框、智能搜索框这类核心入口可以使用 `超级框hover阴影`，但不要用于普通输入框。
- 表格、表单等高密度内容区域不应滥用强投影，否则会降低阅读效率。

## 页面架构规范

### 标准页面结构

推荐结构：

```text
顶部导航 / 顶栏
  ├── Logo / 产品名
  ├── 全局搜索
  ├── 通知
  ├── 用户信息
  └── 全局操作

左侧导航 / 侧边栏
  ├── 一级导航
  ├── 二级导航
  └── 折叠/展开控制

主内容区
  ├── 面包屑
  ├── 页头
  ├── 页面级操作
  ├── 筛选 / 查询区域
  ├── 数据展示区域
  └── 分页 / 批量操作

弹层区
  ├── 弹窗
  ├── 抽屉
  ├── 气泡卡片
  └── 全局提示
```

### 页面类型

| 页面类型 | 主要组件 | 适用场景 |
|---|---|---|
| Dashboard 概览页 | 统计数值、卡片、图表、表格、时间轴 | 总览、态势、运营看板 |
| 列表页 | 筛选区、表格、分页、批量操作、标签 | 数据管理、任务管理、专家管理 |
| 详情页 | 页头、描述列表、标签、时间轴、操作记录 | 查看对象详情、审计记录 |
| 表单页 | 表单、输入框、选择器、日期时间、上传 | 创建、编辑、配置 |
| 分步流程页 | 步骤条、表单、确认页、结果页 | 创建项目、发布智能体、审批流程 |
| 配置页 | 表单、开关、树选择、穿梭框、权限树 | 系统设置、权限配置 |
| 异常页 | 插图、标题、说明、建议操作 | 无权限、404、500、加载失败、维护中 |

### 信息层级

页面信息从高到低建议分为：

1. 页面标题与当前任务。
2. 页面级主操作。
3. 筛选条件与搜索。
4. 关键数据与状态。
5. 明细数据。
6. 辅助说明与元信息。
7. 次级操作与更多操作。

## 导航规范

### 顶部导航

#### 使用场景

- 提供全局级类目和功能。
- 放置产品名称、全局搜索、通知、主题切换、用户账户。
- 适合多模块平台型产品。

#### 设计要求

- 顶部导航应稳定存在，不随页面内容变化频繁改变。
- 全局搜索、通知、头像等位置应固定。
- 顶部导航不应承载过多业务操作，业务操作应放入页面内。

### 侧边导航

#### 使用场景

- 展示产品核心功能模块。
- 承载多级信息架构。
- 适合企业后台、SaaS 平台、复杂系统。

#### 设计要求

- 支持展开和收起。
- 收起态保留图标。
- 当前模块必须有清晰选中态。
- 导航层级不宜过深，超过三级需要重新梳理信息架构。
- 图标必须与模块语义一致，不能只为装饰。

### 面包屑

#### 使用场景

- 系统层级超过两级。
- 用户需要知道“当前在哪里”。
- 用户需要快速返回上级页面。

#### 规则

- 当前层级不需要可点击。
- 上级层级可点击返回。
- 层级名称应与页面标题或导航名称一致。
- 不要用面包屑替代主导航。

### 标签页

#### 使用场景

- 对平级内容进行分类收纳。
- 用于主导航层级之下的页面细分模块。
- 适合三级、四级分类切换。

#### 规则

- 标签页数量建议不超过 5 个。
- 当前选中态必须明显。
- 标签之间应为平级关系，不要混入父子关系。
- 如果内容差异过大，应使用导航或独立页面，而不是标签页。

### 步骤条

#### 使用场景

- 任务复杂且存在前后顺序。
- 用户需要知道当前进度。
- 创建、发布、审批、配置向导等场景。

#### 规则

- 建议多于 2 步、少于 5 步。
- 只有两步能完成的流程不建议使用步骤条。
- 每一步的名称应是结果导向，例如“填写信息”“配置权限”“确认发布”。
- 每一步完成后应保留可回看能力。

### 下拉菜单

#### 使用场景

- 页面操作较多，需要收纳低频操作。
- 表格行操作超过 3–5 个。
- 顶部导航或按钮组合中需要扩展操作。

#### 规则

- 菜单项保持单行显示。
- 面板宽度建议等于或大于触发区域。
- 危险操作需要视觉区分或二次确认。
- 不要把高频主操作藏进下拉菜单。

### 分页

#### 使用场景

- 数据量较大，一次加载影响性能。
- 用户需要切换页码浏览数据。

#### 规则

- 基础页码最多默认展示 5 页。
- 表格无数据时不显示分页。
- 分页应放在数据列表底部右侧或底部区域。
- 支持每页条数切换时，应保持与数据密度匹配。

## AI 原生多智能体平台适配规范

> 如果该规范用于 AgentTeams / 多智能体协作平台，建议在原 B 端规范上增加以下 AI 场景标准。

### AI 能力入口

| 入口类型 | 推荐组件 | 说明 |
|---|---|---|
| 智能生成 | AI 按钮 / 主按钮 | 用于生成报告、方案、摘要 |
| 智能推荐 | AI 按钮 / 卡片推荐区 | 推荐专家、技能、模板 |
| 智能分析 | 图标按钮 / 主按钮 | 分析日志、风险、任务 |
| 自动填充 | 输入框后缀按钮 | 根据上下文补全表单 |
| AI 审核 | 表格行操作 / 抽屉 | 对内容进行风险审核 |
| AI 助手说明 | Tooltip / Popover | 解释模型能力和限制 |

### 智能体状态

| 状态 | 文案 | 颜色建议 |
|---|---|---|
| 正常 | 运行中 | 成功色 |
| 待配置 | 待配置 | 提醒色 |
| 执行中 | 执行中 | 蓝色 / 主色 |
| 异常 | 异常 | 错误色 |
| 暂停 | 已暂停 | 中性色 |
| 审批中 | 审批中 | 警告色 |
| 已下线 | 已下线 | 中性色 |

### AI 任务生命周期

```text
创建任务
  ↓
选择专家 / 智能体
  ↓
配置输入与约束
  ↓
执行中
  ↓
生成结果
  ↓
人工审核
  ↓
应用 / 发布 / 归档
```

#### 设计要求

- 任何 AI 输出都不能默认为最终结果。
- 关键结果必须提供人工审核入口。
- AI 操作记录必须保留来源、输入、输出、执行时间、操作者。
- 失败时需要说明失败原因和重试建议。
- 多智能体协作时需要展示每个智能体的贡献或状态。

### AI 结果展示

推荐结果结构：

```text
结果标题
生成时间 / 使用模型 / 来源数据
核心结论
证据或依据
风险提示
可执行操作：[复制] [编辑] [重新生成] [应用结果]
```

#### 规则

- AI 结果不能只给结论，需要给依据。
- 涉及风险判断时必须展示置信度或不确定性说明。
- 应用 AI 结果前必须允许用户编辑。

## 文案规范

### 基本原则

- 简洁：避免长句。
- 明确：说明用户要做什么。
- 结果导向：让用户知道操作后会发生什么。
- 风险透明：不可逆、覆盖、断开、删除必须说清楚。
- 一致：同类操作使用同类表达。

### 常用文案模板

#### 成功反馈

```text
保存成功
创建成功
提交成功
发布成功
上传成功
```

#### 失败反馈

```text
保存失败，请重试
上传失败，请检查文件格式
加载失败，请刷新重试
提交失败，请检查必填项
```

#### 空状态

```text
暂无数据
暂无任务
暂无搜索结果
暂无可用专家
当前无权限查看该内容
```

#### 确认弹窗

```text
确定删除 {对象} 吗？
删除后将无法恢复，请谨慎操作。
```

#### 离开确认

```text
确定离开当前页面吗？
离开后，未保存的内容将会丢失。
```

#### 前端落地注意事项

- 如果构建链对中文 CSS 变量名、空格变量名兼容性不好，应以英文 alias 为主，中文 Token 只保留在设计文档和 Figma Token 中。
- 重复 Token 不要重复声明：`Blue-7`、`gray-6/7/8/9` 等重复变量在工程里保留一个即可。
- `P6/P7` 是 `p6/p7` 的别名，工程交付统一使用小写。
- 不要把 AI 渐变赋给普通 primary button；普通主按钮继续使用 `p6/p5/p7`。
- 旧项目如果已经使用蓝色作为主色，需要在主题层做映射，不要直接修改语义色。

## 页面设计验收清单

### 全局一致性

- [ ] 页面是否使用统一画板和栅格？
- [ ] 间距是否为 4px 的倍数？
- [ ] 字号、行高、字重是否符合规范？
- [ ] 颜色是否来自统一 Token？
- [ ] 卡片、表格、表单、按钮是否使用统一组件？
- [ ] 页面层级是否清晰？

### 页面架构

- [ ] 用户是否能一眼看懂当前页面任务？
- [ ] 页面标题是否清晰？
- [ ] 面包屑是否正确？
- [ ] 主操作是否明显？
- [ ] 筛选区、内容区、操作区是否分区清楚？
- [ ] 小屏下侧边栏是否能正确收起？

### 表格

- [ ] 表头是否清晰？
- [ ] 单位是否放在表头？
- [ ] 对齐方式是否正确？
- [ ] 文本溢出是否有省略和 Tooltip？
- [ ] 是否有空状态？
- [ ] 是否有分页？
- [ ] 操作列是否过多？
- [ ] 横向滚动时是否冻结主列和操作列？

### 表单

- [ ] 标签是否简洁？
- [ ] 必填项是否清晰？
- [ ] 错误提示是否紧贴控件？
- [ ] 帮助说明是否必要且清楚？
- [ ] 输入框、选择器、日期等组件是否选型正确？
- [ ] 提交失败时是否说明原因？

### 按钮

- [ ] 一个操作区域是否只有一个主按钮？
- [ ] 按钮文案是否表达具体动作？
- [ ] 危险操作是否二次确认？
- [ ] 是否包含 hover / click / disabled / loading 状态？
- [ ] 多个操作是否按主次排列？

### 反馈

- [ ] 成功、失败、警告是否使用正确反馈组件？
- [ ] Message 是否用于轻量反馈？
- [ ] Notification 是否用于系统主动通知？
- [ ] Alert 是否用于常驻警告？
- [ ] Modal 是否用于阻断式确认？
- [ ] 抽屉是否用于不离开当前页面的附加任务？
- [ ] 空状态、异常页是否有下一步操作？

### AI 场景

- [ ] AI 操作是否说明生成内容和影响范围？
- [ ] AI 执行中是否有 Loading 或进度反馈？
- [ ] AI 结果是否可编辑、可审核、可应用？
- [ ] AI 结果是否展示来源或依据？
- [ ] 高风险 AI 操作是否需要人工确认？
- [ ] 是否保留操作日志和审计信息？

### 布局、列表与适配检查

| 检查项 | 合格标准 |
|---|---|
| 布局画板 | 是否以 1440px 为常规设计稿基准 |
| 原子单位 | 布局、间距、尺寸是否使用 4px 倍数 |
| 主流分辨率 | 是否至少检查 1920 / 1440 / 1366 / 1280 |
| 侧边栏断点 | 是否设置 992px 默认断点 |
| 页面最小宽度 | 是否明确 768px 最小宽度和横向滚动策略 |
| 收起侧边栏 | 是否明确 56px 收起态宽度 |
| 列表行高 | 表头和单元格是否统一 40px |
| 列表字号 | 列表文字是否统一 12px |
| 列表间距 | 列表距操作区和分页是否为 8px |
| 操作按钮 | 列表页操作按钮高度是否为 32px，按钮间距是否为 8px |
| 筛选区 | 有标题/无标题筛选项间距是否符合 8A 规则 |
| Dashboard 图表 | 是否为环形、趋势、柱形等图表定义最小宽度 |
| 图表压缩 | 宽度不足时是否横向滚动，而不是强行压缩 |
| 抽屉弹窗 | 是否按 560px / 880px / 80% 三类宽度选择 |
| 表格横向滚动 | 是否固定关键列/操作列并保证表头内容对齐 |


### CSS Token 检查

| 检查项 | 验收标准 |
|---|---|
| 主色 | 普通主操作是否使用 `p6 #00AB7A`，hover 是否使用 `p5`，active 是否使用 `p7` |
| AI 按钮 | AI 功能入口是否使用 `AI 默认 / AI 悬停 / AI 按下` 三态渐变 |
| AI 与普通按钮区分 | 普通保存、提交、筛选、导出按钮是否没有误用 AI 渐变 |
| 中性色 | 背景、hover、边框、分割线、正文、标题是否分别调用正确 `gray-*` |
| 功能色 | 成功、警告、错误、信息是否使用对应 Green / Orange / Red / Blue Token |
| 安全等级 | 致命、严重、高危、中危、低危、安全是否按 Deep red / Red / Orange red / Orange / Yellow / Green 映射 |
| Focus ring | 表单聚焦、错误、成功、警告状态是否使用 2px 外描边 Token |
| 投影 | 卡片是否用一级投影；弹窗/抽屉是否用二级投影；AI 超级输入框 hover 是否用专门阴影 |
| 重复变量 | 是否清理了 `P6/P7`、重复 `Blue-7`、重复 `gray-*` 等冗余声明 |
| 工程命名 | 是否为中文 Token 建立英文 alias，避免工程兼容问题 |

## 最终落地建议

这套规范最值得继承的不是某一个颜色或某一个按钮样式，而是它的组织逻辑：

1. **先统一全局 Token**：颜色、字体、间距、栅格、投影。
2. **再统一页面骨架**：顶部、侧栏、内容区、弹层区。
3. **再统一组件选型**：什么时候用表格，什么时候用卡片，什么时候用抽屉。
4. **最后统一业务反馈**：尤其是删除、禁用、覆盖、发布、审批等敏感场景。

对于 AI 原生平台，不建议一味追求“科技感”。真正能提升产品质感的是：  
**清晰的信息架构、稳定的组件体系、可预期的交互反馈、透明的 AI 结果解释，以及关键操作的安全确认。**
