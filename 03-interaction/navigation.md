# 导航交互规范
## Navigation Interaction Rules

Keywords: navigation, top nav, sidebar, breadcrumb, tabs, steps, dropdown, pagination

本文定义后台系统中的顶部导航、侧边导航、面包屑、标签页、步骤条、下拉菜单和分页规则。AI 生成后台页面、Vue 代码或 HTML 预览文件时，应根据页面复杂度选择合适的导航组件。

## 1. 导航定位

导航组件用于帮助用户理解：

```text
我在哪里
→ 能去哪里
→ 当前任务属于哪个层级
→ 下一步可以做什么
```

导航不只是视觉结构，而是系统信息架构的外化表达。顶部导航、侧边导航、面包屑、标签页、步骤条和分页应各司其职，不应互相替代。

## 2. 顶部导航

### 2.1 使用场景

- 提供全局级类目和功能。
- 放置产品名称、全局搜索、通知、主题切换、用户账户。
- 适合多模块平台型产品。

### 2.2 设计要求

- 顶部导航应稳定存在，不随页面内容变化频繁改变。
- 全局搜索、通知、头像等位置应固定。
- 顶部导航不应承载过多业务操作，业务操作应放入页面内。
- 顶部导航与侧边导航共同构成全局控制层。
- 顶部导航用于全局跳转和系统级控制，不承载局部筛选条件。

## 3. 侧边导航

### 3.1 使用场景

- 展示产品核心功能模块。
- 承载多级信息架构。
- 适合企业后台、SaaS 平台、复杂系统。

### 3.2 设计要求

- 支持展开和收起。
- 收起态保留图标。
- 当前模块必须有清晰选中态。
- 导航层级不宜过深，超过三级需要重新梳理信息架构。
- 图标必须与模块语义一致，不能只为装饰。
- 侧边导航负责模块定位，不应混入页面临时筛选项。

## 4. 面包屑

### 4.1 使用场景

- 系统层级超过两级。
- 用户需要知道“当前在哪里”。
- 用户需要快速返回上级页面。

### 4.2 规则

- 当前层级不需要可点击。
- 上级层级可点击返回。
- 层级名称应与页面标题或导航名称一致。
- 不要用面包屑替代主导航。
- 面包屑不应过长，层级过深时应反查信息架构是否过度复杂。

## 5. 标签页

### 5.1 使用场景

- 对平级内容进行分类收纳。
- 用于主导航层级之下的页面细分模块。
- 适合三级、四级分类切换。

### 5.2 规则

- 标签页数量建议不超过 5 个，系统设置类页面可放宽到 7 个。
- 当前选中态必须明显。
- 标签之间应为平级关系，不要混入父子关系。
- 如果内容差异过大，应使用导航或独立页面，而不是标签页。
- 标签页切换时应只替换当前内容区，不应改变全局导航结构。

## 6. 步骤条

### 6.1 使用场景

- 任务复杂且存在前后顺序。
- 用户需要知道当前进度。
- 创建、发布、审批、配置向导等场景。

### 6.2 规则

- 建议多于 2 步、少于 5 步。
- 只有两步能完成的流程不建议使用步骤条。
- 每一步的名称应是结果导向，例如“填写信息”“配置权限”“确认发布”。
- 每一步完成后应保留可回看能力。
- 当前步骤、已完成步骤和未完成步骤必须视觉可区分。
- 返回上一步如果影响后续数据，必须提示影响范围。

## 7. 下拉菜单

### 7.1 使用场景

- 页面操作较多，需要收纳低频操作。
- 表格行操作超过 3 到 5 个。
- 顶部导航或按钮组合中需要扩展操作。

### 7.2 规则

- 菜单项保持单行显示。
- 面板宽度建议等于或大于触发区域。
- 危险操作需要视觉区分或二次确认。
- 不要把高频主操作藏进下拉菜单。
- 菜单项文案必须是动作，不要使用模糊名词。

## 8. 分页

### 8.1 使用场景

- 数据量较大，一次加载影响性能。
- 用户需要切换页码浏览数据。

### 8.2 规则

- 基础页码最多默认展示 5 页。
- 表格无数据时不显示分页。
- 分页应放在数据列表底部右侧或底部区域。
- 支持每页条数切换时，应保持与数据密度匹配。
- 分页应包含总数、页码、上一页 / 下一页和每页条数。
- 总数文案建议使用 `共计 N 条` 或产品统一格式。

## 9. 导航组件选择规则

| 场景 | 推荐组件 | 不建议 |
|---|---|---|
| 全局模块跳转 | 顶部导航 / 侧边导航 | 用标签页模拟一级导航 |
| 当前页面下的平级分类 | 标签页 | 使用多个侧边导航层级 |
| 层级定位与返回 | 面包屑 | 用面包屑替代主导航 |
| 明确顺序流程 | 步骤条 | 用标签页模拟步骤 |
| 低频扩展操作 | 下拉菜单 | 把主操作藏进下拉菜单 |
| 大量数据浏览 | 分页 | 无限堆叠数据导致页面过长 |

## 10. AI / Vue 生成要求

- AI 生成完整后台页面时，不能缺少顶部导航和侧边导航。
- 层级超过两级的页面应展示面包屑。
- 平级分类页面优先使用标签页，不要滥用二级侧边导航。
- 有明确顺序的复杂流程应使用步骤条。
- 低频操作可收进下拉菜单，但主操作不能隐藏。
- Vue 代码应使用可维护的导航数据结构，不要把导航项散落在模板中。
- HTML 预览文件应至少模拟一种导航交互，例如标签页切换、侧栏收起或分页切换。
