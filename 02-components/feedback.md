# 反馈与异常组件规范
## Feedback and Exception Component Rules

Keywords: feedback, message, notification, alert, modal, drawer, loading, progress, empty, exception

本文定义后台页面中的反馈组件，包括全局提示、通知提醒框、警告提示、弹窗、气泡确认、抽屉、加载中、进度条、空状态和异常页面。

## 1. 全局提示 Message

### 1.1 使用场景

- 用户主动操作后的轻量反馈。
- 只需要阅读，不需要后续操作。
- 加载完成、保存成功、删除失败等。

### 1.2 规则

- 位于页面顶部居中。
- 约 3 秒后自动消失。
- 不打断用户操作。
- 类型仅保留常规、成功、预警、失败。
- 文案尽量短，例如“保存成功”“删除失败，请重试”。

## 2. 通知提醒框 Notification

### 2.1 使用场景

- 系统主动推送。
- 后台任务完成。
- 工作流结果通知。
- 复杂内容提醒。

### 2.2 规则

- 出现在页面角落。
- 不遮挡关键内容。
- 内容比 Message 更复杂。
- 可包含标题、说明和操作入口。
- 不重要通知应进入消息中心，不要弹出打扰用户。

## 3. 警告提示 Alert

### 3.1 使用场景

- 页面级重要提示。
- 用户需要持续关注的警告信息。
- 常驻展示，不自动消失。

### 3.2 规则

- 可关闭，但关闭前不应影响理解。
- 用于整个页面或模块提示。
- 不适合直接用于弹窗内复杂提示，弹窗内应改为轻量文字说明。
- 文案应说明问题、影响和建议操作。

## 4. 弹窗 Modal

### 4.1 使用场景

- 用户必须确认后才能继续。
- 高风险操作确认。
- 短表单或结果反馈。
- 阻断当前流程的关键动作。

### 4.2 规则

- 弹窗必须有明确标题。
- 标题要说明动作和对象。
- 描述要说明后果。
- 主按钮文案不要只写“确定”，应尽量写明动作，如“确认删除”。
- 不可逆操作使用危险按钮。

### 4.3 高风险操作反馈模板

```text
标题：确定 {动作} {对象} 吗？
说明：{动作} 后 {结果}，请谨慎操作。
增强说明：{进一步业务影响或恢复方式}
按钮：[取消] [确认{动作}]
```

示例：

```text
标题：确定删除客户端策略吗？
说明：删除后将无法恢复，请谨慎操作。
增强说明：删除后客户端将无法执行该策略，请确认后继续。
按钮：[取消] [确认删除]
```

## 5. 气泡确认框 Popconfirm

### 5.1 使用场景

- 目标元素附近的轻量二次确认。
- 表格行内删除、停用、移除等操作。
- 操作风险较低，但需要用户确认。

### 5.2 规则

- 只用于确认操作。
- 不承载复杂表单。
- 不承载详细说明。
- 高风险不可逆操作应使用 Modal，而不是 Popconfirm。

## 6. 抽屉 Drawer

### 6.1 使用场景

- 在不离开当前页面的情况下插入附加任务。
- 查看详情。
- 编辑辅助信息。
- 配置筛选条件。
- 表格行详情。

### 6.2 规则

- 从页面边缘滑出。
- 覆盖部分父页面。
- 用户完成后能平滑回到原任务。
- 不适合承载特别复杂的多步骤流程。
- 抽屉宽度要根据内容复杂度设置。
- 抽屉使用二级投影，与普通卡片层级区分。

## 7. 加载中 Loading

### 7.1 使用场景

- 页面或区块异步加载。
- 数据渲染等待。
- AI 生成中。
- 文件上传中。

### 7.2 规则

- 加载时间较短时使用轻量 Loading。
- 超过 2 秒的任务建议显示进度或说明。
- AI 生成类任务应说明当前状态，例如“正在分析日志”“正在生成报告”。
- 加载失败必须给出重试入口。

## 8. 进度条 Progress

### 8.1 使用场景

- 操作耗时较长。
- 需要显示完成百分比。
- 后台任务执行。
- 上传、扫描、生成、部署。

### 8.2 规则

- 超过 2 秒的任务建议显示进度。
- 支持成功、失败、处理中状态。
- 不能准确计算进度时，可以使用阶段进度或环形进度。
- 完成后需要结果反馈。

## 9. 空状态 Empty

### 9.1 使用场景

- 数据为空。
- 搜索无结果。
- 暂无任务。
- 暂无通知。
- 暂无权限下的数据入口。

### 9.2 规则

- 不要只显示空白。
- 需要包括：插图、标题、说明、可选操作。
- 如果用户可以创建数据，应提供创建入口。
- 如果用户无权限，应说明原因和申请方式。
- 图标插图建议使用统一画板，例如 120 × 120。

## 10. 异常页面

### 10.1 使用场景

- 无权限。
- 网络不可用。
- 系统维护。
- 加载失败。
- 404。
- 500。

### 10.2 规则

- 由插图、标题、说明、建议操作组成。
- 标题最多一行。
- 说明解释发生了什么。
- 操作给出下一步，如“返回首页”“刷新重试”“联系管理员”。
- 不同异常类型使用统一视觉风格。

## 11. Vue / HTML 生成要求

- Vue 代码优先使用 `a-message`、`a-notification`、`a-alert`、`a-modal`、`a-popconfirm`、`a-drawer`、`a-spin`、`a-progress`、`a-empty`、`a-result` 等组件能力。
- 所有用户触发操作都应有结果反馈。
- 高风险操作必须有确认，不只使用 Toast。
- HTML 预览文件应至少模拟一种确认弹窗、一种 Toast、一种 loading、一种空状态或异常状态。
