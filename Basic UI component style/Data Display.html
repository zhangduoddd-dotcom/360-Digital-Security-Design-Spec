Table 表格

Table 表格

用于展示多条结构类似的数据，可排序、筛选、对比和批量操作。表格作为多维信息展示载体，使复杂信息更易查询、理解和处理。

Ant: Table

使用场景

当有大量结构化数据需要展现时；当需要对数据进行排序、搜索、分页、自定义操作等复杂行为时。

表格规则

  1. 布局：为适应多分辨率要求，表格默认采用百分比布局，列较多时允许横向滚动。
  2. 表头：单位统一放在表头内，表头文本不建议换行展示；关系性强的字段应靠近排列。
  3. 对齐：链接、名称、信息、日期、姓名等文本左对齐；详细数值可右对齐。
  4. 冻结：执行状态、操作栏等高频字段可固定展示，避免横向滚动时丢失上下文。
  5. 排序：通常按业务默认顺序排序，可点击表头升序、降序切换。
  6. 筛选：隐藏属性可通过筛选浮层查看或选择；高频筛选字段应放在表格上方。
  7. 文本：过长内容默认省略，鼠标 hover 后通过 Tooltip 展示完整内容。
  8. 为空：空值统一显示 -，不展示空白单元格。
  9. 操作：高频操作不超过 3 个，更多操作收起到“更多”。

用于解释图标、长文本、表头操作和截断字段，只承载短说明。

Ant: Tooltip

使用场景

可用来代替系统默认的 title 提示，提供一个按钮 / icon / 文字 / 操作的文案解释。

Card 卡片

通用卡片容器。

Ant: Card

使用场景

- 可承载文字、列表、图片、段落，常用于后台概览页面，将一组相关信息或类似的任务组合在一起，使用户更容易浏览和完成任务。

体系定位

卡片是页面中的信息容器，用于把同类内容收束成一个可浏览、可比较、可操作的独立区域。

内容承载

适合承载标题、描述、列表、图片、统计数值和轻量操作，不用于承载复杂流程或长表单。

页面场景

常用于概览页、详情页、配置页和任务面板，帮助用户快速识别一组相关信息。

组合规则

同一区域内卡片宽高、标题层级和内边距保持一致，避免不同信息组之间视觉权重失衡。

结构拆分

标题区

  • 标题用于概括卡片主题，默认高度 56px。
  • 标题与内容之间使用 1px 灰色分割线。
  • 操作入口放在标题右侧时，应保持轻量和明确。

内容区

  • 内容区默认左右 24px、上下 16px。
  • 文本内容控制行高和段落间距，避免卡片内部拥挤。
  • 同组卡片内容密度尽量一致，便于横向浏览。

样式规则

独立卡片

  • 白色页面背景中使用 1px 灰色边框区分卡片边界。
  • 需要强调层级时可叠加轻投影，但不改变内容结构。
  • 卡片圆角保持 2px-8px 范围，跟随全局规范。

区域承载

  • 灰色页面区域中卡片保持白底，形成稳定的信息承载面。
  • 多卡片排列时使用统一栅格间距，避免卡片贴边。
  • 卡片不嵌套卡片，复杂内容拆分为列表、描述或表格组件。

Popover 气泡卡片

Popover 承载简短详情和轻量操作；短说明继续使用 Tooltip。

Ant: Popover

使用场景

体系定位

用于承载触发对象的补充说明、状态摘要和轻量操作，定位介于 Tooltip 与 Modal 之间。

解释说明轻操作

独立组件

气泡卡片作为独立浮层组件使用，不改变原页面结构，触发元素负责控制显示与关闭。

hoverclick外部关闭

尺寸规则

内容宽度随信息量收敛，短内容使用紧凑宽度；说明、列表和操作内容保持统一内边距。

最小 180px内边距 12/16

核心 Token

沿用全局白底、灰色描边、轻阴影和主色操作链接，保证与表格、标签等组件视觉一致。

#FFFFFF#E8EAEDPrimary

- 纯文本加链接（建议链接不多于2个）；
