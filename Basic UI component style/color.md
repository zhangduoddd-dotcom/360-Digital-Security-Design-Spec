# 语义色与状态标签规范
## Color Semantics and Status Label Rules

Keywords: color, brand color, status, semantic color, status label, level label, risk level, security, chart, data visualization

本文定义后台产品中的品牌主色、语义色、状态色、风险色、等级标签、状态标签、默认标签、状态点和图表用色规则。所有列表页、详情页、工作台、表单页、图表可视化、AI 生图 Prompt、Vue 代码生成和 Ant Design Vue 高保真样式覆盖都必须遵循本文。

## 1. 品牌主色

品牌主色为科技绿，核心色为 `p6 #00AB7A`。所有主色相关组件，包括主按钮、选中状态、强调文本、聚焦边框、开关开启态、Radio / Checkbox 选中态等，必须从 `p1-p10` 品牌色阶中取色，不允许随机取近似绿色。

### 1.3 Ant Design Vue 品牌色落地规则

AI 生成 Ant Design Vue 页面时，所有主色相关组件必须被映射到品牌色：

- `a-button type="primary"`：默认 p6，hover p5，active p7，文字白色。
- `a-input`、`a-select`、`a-date-picker` 聚焦态：边框 p6，外发光 p1。
- `a-radio`、`a-checkbox` 选中态：背景 p6，边框 p6。
- `a-switch` 开启态：背景 p6。
- `a-tabs` 选中态、下划线、活动色：使用 p6。
- 链接、强调文本、可点击主色文本：默认 p6，hover p5，active p7 或 p8。
- Tag 的默认品牌样式：背景 p1，文字 p6，无边框或弱边框。

普通组件不允许继续保留 Ant Design Vue 默认蓝色主色，除非该蓝色表达的是“信息 / 链接 / 进行中”等语义色。

## 5. 标签通用规则

1. 一致性原则：同一系统中，同一维度标签在不同页面类型出现时，应尽量保持样式一致。
2. 标准化原则：使用系统统一定义的标签样式，优先使用默认标签样式。
3. 替代规则：结果类、状态标签在表格中出现时，可使用状态点替代 icon，降低噪音。
4. 文字规则：标签不能只依赖颜色表达，必须保留文字。
5. 命名规则：等级、状态、结果文案必须使用本文定义的标准命名，不要随意改写成近义词。

## 6. 标签降噪规则

1. 为保证系统最重要状态清晰，整个系统的面性标签类别建议不超过 3 类。
2. 表格中有多个等级标签时，尽量只保留一个最高优先级等级为面性标签，其他等级使用线性加面性标签。
3. 操作状态较多时，非重要状态可用状态点代替 icon。
4. 一个单元格内不宜堆叠过多彩色标签。
5. 普通分类标签优先使用默认标签，不要滥用风险色。

## 7. 标签样式类型

| 标签类型 | 使用场景 | 样式规则 |
|---|---|---|
| 面性标签 | 标识最重要信息、需用户优先识别的等级 | 底色使用对应语义色 `-6`，文字色使用 #FFFFFF |
| 线性加面性标签 | 标识较重要信息、需用户快速识别的等级 | 底色使用对应语义色 `-1`，文字色使用对应语义色 `-7` |
| icon + 文字标签 | 解释性 / 描述性状态 / 结果信息 | icon 使用对应语义色 `-6`，文字色使用 #525966 |
| 状态点 + 文案 | 非重要结果、严重等级、操作进程 | 状态点使用对应语义色 `-6`，圆点后保留文案 |
| 默认标签 | 无需区分状态、仅展示标签内容 | 使用灰色描边或浅灰底 |
| 强调默认标签 | 默认标签中需要强调信息优先级 | 可使用蓝色信息标签 |

## 8. 等级标签命名标准

等级标签用于功能模块中标识风险、告警、事件、威胁、漏洞、脆弱性、资产风险等用户需要优先识别的信息。

| 场景分类 | 标准等级 / 状态命名 | 说明 |
|---|---|---|
| 告警 - 告警级别 | 紧急、严重、警告、提醒 | 用于告警列表、告警详情、告警统计 |
| 安全事件 - 事件级别 | 紧急、严重、警告、提醒 | 与告警级别保持一致，避免同义词混用 |
| 攻击者 - 威胁等级 | 紧急、高危、中危、低危、无风险、未知 | 用于攻击者画像、威胁分析、风险识别 |
| 漏洞等级 | 超危、高危、中危、低危、信息 | 用于漏洞列表、漏洞详情、漏洞统计 |
| 脆弱性 - 威胁等级 | 超危、高危、中危、低危、信息 | 与漏洞等级保持一致 |
| 风险资产 - 风险等级 | 已失陷、高风险、中风险、低风险、无风险 | 用于资产风险、终端风险、业务风险资产 |

### 8.1 等级标签用色建议

| 等级语义 | 推荐色系 | 典型命名 |
|---|---|---|
| 最高风险 / 致命 | 深红 | 超危、已失陷、紧急 |
| 严重风险 | 红色 | 严重、高危、高风险 |
| 高风险提醒 | 深橙 | 警告、中危、中风险 |
| 中低风险提醒 | 橙色 / 黄色 | 低危、低风险、提醒 |
| 信息 / 提示 | 蓝色 / 灰色 | 信息、未知 |
| 安全 / 无风险 | 绿色 | 无风险、安全、正常 |

## 9. 状态标签命名标准

状态标签用于功能模块中提供解释性、描述性的状态或结果信息。

| 场景分类 | 标准状态 / 结果命名 | 说明 |
|---|---|---|
| 研判结果 | 攻击成功、误报、攻击失败、未研判 | 用于安全事件研判、告警研判、分析结论 |
| 处置状态 | 待处置、处置中、处置完成、忽略、处置失败 | 用于工单、告警、事件、风险处置流转 |
| 置信度 | 高置信、中置信、低置信、未知 | 用于 AI 分析、检测结果、威胁情报、模型判断 |

## 10. 默认标签与普通多彩标签

### 10.1 默认标签

适用场景：无需区分状态、仅展示标签内容。

示例：

```text

```

特殊说明：如需在默认标签中区分信息优先级，可使用蓝色信息标签进行强调。

### 10.2 其他状态标签

其他非特定内容可使用普通多彩标签，但必须遵循语义色规则，不允许自定义随机色。

## 12. 状态点 + 文案规范

状态点用于表示非重要的结果、严重等级、操作进程等。

| 项目 | 规则 |
|---|---|
| 圆点尺寸 | 6px × 6px |
| 与文字间距 | 4px |
| 圆点颜色 | 使用对应语义色 `-6` |
| 文案 | 必须保留，不只展示圆点 |
| icon | 状态点无需搭配 icon |

### 12.1 核心状态点语义色

| 颜色 | 色值 | 语义说明 |
|---|---|---|
| 红色 Red-6 | #F0131E | 失败、阻断、不可用、严重异常 |
| 橙色 Orange-6 | #F58A02 | 异常、预警、轻微问题、不阻断流程 |
| 蓝色 Blue-6 | #1890FF | 进行中、待处理、待审批、正常流转 |
| 绿色 Green-6 | #52C41A | 启动、成功、完成、正常运行 |
| 灰色 gray-6 | #AEB2B8 | 草稿、已停止、用户主动终止、禁用状态 |

> 深红色、深橙色为多级等级专属定义色，不用于常规流程颜色。

### 13.1 流程节点状态

| 流程状态 | 推荐颜色 |

| 开关状态 | 推荐颜色 |
|---|---|
| 启动 / 开启 | 绿色 |

| 连接状态 | 推荐颜色 |
|---|---|

## 14. 图表色（chart）

图表色用于柱状图、折线图、面积图、饼图、环图、散点图、雷达图等数据可视化场景。图表用色必须先判断业务语义，再判断是否使用图表专用色；不得为了视觉丰富覆盖风险、状态或场景语义。

### 14.1 图表用色优先级

1. 当图表标题、图例、维度字段、分组字段、指标名称或数据项明确指向本文第 8 节“等级标签命名标准”中的内容时，图表颜色必须对应等级标签用色，不使用图表专用色。典型内容包括：紧急、严重、警告、提醒、超危、高危、中危、低危、信息、已失陷、高风险、中风险、低风险、无风险等。
2. 当图表明确指向本文第 13 节“三大场景用色规则”中的流程节点状态、功能开关状态或数据连接状态时，图表颜色必须对应场景状态用色，不使用图表专用色。典型内容包括：待处理、审批中、流转中、完成、结束、失败、失效、阻断、启动、开启、停止、关闭、连接正常、轻微异常、阻断性故障等。
3. 当图表内容不属于第 8 节等级语义，也不属于第 13 节场景状态，例如普通分类、业务对象、渠道、地区、资产类型、产品类别、时间分组对比等，使用图表专用色。

### 14.3 图表专用色使用顺序

1. 普通分类型图表按数据系列顺序优先依次使用基础色：`c1`、`c3`、`c5`、`c7`、`c9`、`c11`、`c13`、`c15`、`c17`、`c19`。
2. 基础色使用完后，再依次使用扩展色：`c2`、`c4`、`c6`、`c8`、`c10`、`c12`、`c14`、`c16`、`c18`、`c20`。
3. 20 个图表专用色全部使用完后，才允许随机取色；随机色需避免与已使用颜色过近，并保持同一数据项在图例、Tooltip、数据标签和图形元素中的颜色一致。
4. 同一个页面内，同一业务维度在多个图表中出现时，应保持颜色映射一致；不要在不同图表中让同一分类使用不同颜色。
5. 图表专用色仅用于无明确风险、状态或场景语义的分类区分，不得用于替代等级标签色、状态色或三大场景状态色。

## 15. 约束规则

1. 流程未结束时，禁止使用红色、绿色表达最终结果。
2. 草稿状态禁止使用蓝色、橙色。
3. 同一状态只允许使用一种语义色，不混用、不自定义。
4. 深红色、深橙色只用于多级风险 / 等级标签，不用于普通流程状态。
5. Ant Design Vue 默认蓝色不得作为产品主色继续使用；主色必须使用 p6 体系。
6. AI 生成页面时，等级标签命名必须优先使用本文第 8 节和第 9 节中的标准文案。
7. Vue 代码生成时，状态枚举、标签文案、mock 数据状态值必须与本文标准命名保持一致。
8. 图表用色必须先匹配本文第 8 节等级标签和第 13 节三大场景，再使用第 14 节图表专用色；不得把图表专用色用于有明确等级或状态语义的数据。

## 16. AI 生成提示

当 AI 生成安全类列表页、详情页、工作台、图表可视化或 Vue 代码时，应优先复用以下标签命名：

```text
紧急、严重、警告、提醒
超危、高危、中危、低危、信息
已失陷、高风险、中风险、低风险、无风险
攻击成功、误报、攻击失败、未研判
待处置、处置中、处置完成、忽略、处置失败
高置信、中置信、低置信、未知
```

不要将“高危”改成“高级风险”，不要将“未研判”改成“未判断”，不要将“处置完成”改成“已完成处置”。标准命名用于保证跨页面、跨组件和 AI 生成结果一致。
