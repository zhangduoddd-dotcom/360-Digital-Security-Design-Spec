# 布局与间距规范
## Layout and Spacing

Keywords: layout, spacing, grid, responsive, sidebar, dashboard, backend

本文定义后台页面的布局骨架、响应式策略、栅格系统、盒子模型和间距规则。AI 生成页面、Vue 代码或 HTML 预览时，必须优先遵循本文。

## 1. 布局定义

空间布局是体系化设计的起点。页面整体布局是产品最外层的框架结构，一般包含导航、侧边栏、面包屑、内容区、弹层等。

布局需要从动态、体系化的角度处理界面空间秩序，让用户在复杂 B 端任务中能够快速识别页面结构和操作路径。

对于企业级 SaaS / B 端后台 / AI 原生协作平台，布局不是装饰问题，而是信息组织、任务优先级和操作效率的问题。

## 2. 布局设计原则

| 原则 | 解释 | 落地要求 |
|---|---|---|
| 一致性 | 产品布局在结构和视觉上保持一致 | 同类页面使用同一布局骨架；同类模块保持相同间距、卡片结构和操作区位置 |
| 可适配 | 布局根据浏览器宽度和屏幕分辨率响应 | 支持 1920 / 1440 / 1366 / 1280 等主流分辨率；内容区自适应 |
| 可控性 | 页面简单、直白、可识别 | 主任务清晰；复杂功能可扩展；页面结构能随业务复杂度延展 |

## 3. 布局执行原则

| 项目 | 标准 |
|---|---|
| 默认设计画板 | 1440px |
| 主流适配宽度 | 1920px、1440px、1366px、1280px |
| 最小原子单位 | 4px |
| 间距计算方式 | `间距 = x × 4px` |
| 栅格体系 | 12 栅格 |
| 常见布局方式 | T 字形布局、左右布局、上下布局 |
| 内容区 | 响应式区域 |
| 页面最小宽度 | 768px |
| 设计输出原则 | 统一画板尺寸输出布局，适配方案遵循一致的响应式布局原则 |

## 4. 页面四层框架

根据用户操作行为进行层级区分，页面框架可分为四层。设计时应从下到上建立信息层级，避免所有内容同时争抢视觉注意力。

| 层级 | 内容 | 说明 |
|---|---|---|
| 背景区域 | 页面底色、背景纹理、全局背景 | 提供环境氛围，不承担主要信息表达 |
| 内容层 | 表格、列表、卡片、图表、表单、工作区 | 用户完成任务的主要区域 |
| 全局控制层 | 顶部导航、侧边导航、全局搜索、通知、账户入口 | 负责全局跳转、系统级操作和跨页面控制 |
| 内容弹层 | 弹窗、抽屉、气泡确认框、浮层详情 | 承载临时任务、确认、补充说明和局部编辑 |

## 5. 响应式布局定义

响应式布局是指在不同分辨率下，让内容以最优展示形式呈现给用户。

执行要求：

- 使用基于百分比的计算，而不是完全依赖固定像素。
- 图像、卡片、图表和内容区域应可缩放。
- 通过断点控制布局切换。
- 容器可以固定，也可以根据断点流体变化；最终以设计输出要求为准。
- 当宽度小于断点临界值时，卡片宽度应基于可用宽度自适应，同时必须考虑卡片最小宽度。

## 6. 响应式断点与侧边栏策略

| 视窗宽度 | 栅格列数 | Gutter | Margin | 侧边栏收起动作 | 展开动作 | 展开方式 |
|---|---:|---:|---:|---|---|---|
| `< 768px` | 4 | 16px | 24px | 自动完全收起 | 点击按钮展开 | Overlay |
| `768px–991px` | 8 | 16px | 24px | 自动收起，展示图标 | 点击按钮展开 | Push |
| `992px–1199px` | 12 | 24px | 24px | 点击按钮收起，展示图标 | 点击按钮展开 | Push |
| `≥ 1200px` | 12 | 24px | 24px | 点击按钮收起，展示图标 | 点击按钮展开 | Push |

补充规则：

- 侧边栏区域可设置为响应式布局。
- 当浏览器宽度小于配置断点值时，侧边导航自动从展开态变为收起态。
- 默认侧边栏响应断点为 992px。
- 页面最小宽度定义为 768px。
- 收起态侧边栏宽度定义为 56px。
- 当内容区域小于 768px 时，页面不再继续缩小，浏览器应出现横向滚动条。

## 7. 主流分辨率适配逻辑

| 分辨率 | 适配逻辑 |
|---|---|
| 1920px | 左侧导航栏固定，右侧内容区域基于内容自适应 |
| 1440px | 左侧导航栏固定，右侧内容区域基于内容自适应 |
| 1366px | 左侧导航栏固定，右侧内容区域基于内容自适应 |
| 1280px | 左侧导航栏固定，右侧内容区域基于内容自适应 |

## 8. 栅格系统

| 项目 | 规范 |
|---|---|
| 栅格体系 | 12 栅格 |
| 主要适用 | Dashboard、概览页、统计页、卡片流、分析页 |
| Column | 弹性布局 |
| Gutter | 16px 或 24px，常规桌面场景优先 24px |
| Margin | 常规桌面场景优先 24px |
| 盒子模型 | Border & Corner、Padding、Margin、Background、Shadow、Content、Size |

## 9. 卡片栅格划分

| 栅格占比 | 页面呈现 | 适用场景 |
|---|---|---|
| 1 | 一行 1 个大卡片 | 大图表、核心工作区、复杂表单 |
| 1/2 + 1/2 | 一行 2 个卡片 | 左右并列分析、双指标对比 |
| 1/3 + 1/3 + 1/3 | 一行 3 个卡片 | 常规 Dashboard 指标区 |
| 1/4 × 4 | 一行 4 个卡片 | 小型统计卡片、状态概览 |
| 1/5 × 5 | 一行 5 个卡片 | 较高密度指标展示，需谨慎控制文本量 |
| 1/6 × 6 | 一行 6 个卡片 | 极高密度状态入口，不建议承载复杂图表 |
| 1/12 × 12 | 细粒度栅格 | 仅用于布局对齐，不建议直接作为业务卡片宽度 |

## 10. 盒子模型

每一个卡片在前端实现时都应被视为一个盒子。

```text
Box = Border & Corner + Padding + Margin + Background + Shadow + Content + Size
```

| 属性 | 含义 | 推荐标准 |
|---|---|---|
| Border & Corner | 边框与圆角 | 保持同类卡片统一 |
| Padding | 内边距 | Dashboard 卡片常规使用 24px；高密度列表可适当压缩 |
| Margin | 外边距 | 模块之间依据 12px / 16px / 24px 控制 |
| Background | 背景 | 白色或浅灰卡片背景，避免破坏数据阅读 |
| Shadow | 投影 | 轻投影，仅用于层级区分 |
| Content | 内容 | 文本、图表、表格、操作区 |
| Size | 尺寸 | 依据栅格和断点自适应 |

## 11. 栅格响应策略

| 断点 | 响应区间 | 推荐布局 |
|---|---|---|
| 1200px | `> 1200px` | 多列布局，可承载多个并列模块 |
| 992px | `992px–1199px` | 减少横向列数，优先保证主要模块完整 |
| 768px | `768px–991px` | 进一步减少列数，卡片逐步纵向堆叠 |
| `< 768px` | 小于最小页面宽度 | 不再压缩页面，出现横向滚动条 |

强制要求：

- 卡片宽度不能无限缩小。
- 图表类卡片必须定义最小宽度。
- 信息展示完整性优先于强行适配一屏。
- 页面宽度不足时，应通过换行、堆叠、横向滚动处理，而不是压缩到不可读。

## 12. 间距建议

| 场景 | 建议 |
|---|---|
| 页面边距 | 24px |
| 常规卡片内边距 | 24px |
| Dashboard 卡片之间 | 12px / 16px / 24px，根据密度选择 |
| 列表页卡片间距 | 优先 12px，部分卡片场景可使用 16px |
| 标题与内容 | 8px / 12px / 16px |
| 操作按钮之间 | 列表页统一 8px；非高密度页面可使用 12px |
| 模块分组之间 | 16px / 24px |

## 13. AI 生成与前端落地要求

- AI 生图时必须体现稳定页面骨架，不要用装饰图形替代真实布局。
- Vue 代码和 HTML 预览文件中，页面布局必须体现断点、内容区自适应、侧边栏收起、横向滚动等策略。
- Dashboard、概览页、统计页必须按栅格划分卡片，不要让卡片宽度随机。
- 列表页、表格页、配置页在 1280px 下必须仍可阅读；必要时允许横向滚动。
